# 연세 글로벌 한국어 — 리뉴얼

**한국어를 배우는 외국인 학습자**가 연세 글로벌 한국어 교재(한글 · 1급~8급)를
휴대폰으로 학습하는 앱이다. 한 과를 열면 어휘·문법·듣기·읽기·말하기가 활동 일곱 종으로
펼쳐지고, 교재 밖에는 게임 다섯과 표현클립이 있다. 화면 언어는 다섯이고
학습 대상(문항·지문·대화문)은 한국어로 고정한다. 그 학생용 앱을 리뉴얼하는 작업 저장소다.

> **제품을 처음 접한다면 `docs/masterplan_v3.html` 의 §0 부터 읽어라.**
> 누가 쓰나 · 교재가 어떤 모양인가 · 화면 다섯이 무엇인가 · 무엇이 무료인가가
> 한 절에 있다. 아래 셋은 그다음이다.

> **현재 개발 상태는 `docs/status.generated.md` 한 곳만 본다.** 원본은
> `docs/project_status.json`이고 상태는 완료·부분완료·미구현·검증 안 됨 네 개뿐이다.
> `check_docs.py`의 초록불은 문서 **구조** 검사 통과이지 문서 의미 전체의 보증이 아니다.

문서가 여럿인데 **처음에 볼 것은 셋뿐이다.**

무엇이 갖춰졌고 **무엇이 빠졌는지**는 정본 기획서 `docs/masterplan_v3.html`
**§2 덮개 지도**에 있다 — 영역 × 산출물 표이고 **빈 칸이 곧 빠진 기획이다.**

## 이 저장소가 쓰는 세 장치

리뉴얼 작업에서 만든 것이고, **셋 다 사람 눈 대신 스크립트가 판정한다.**
문서가 작업을 저절로 따라오지 않기 때문이다. **지금은 CI 가 대신 돌린다**(아래).

```bash
python3 docs/check_docs.py                          # 문서
cd app && pnpm parity:activity                        # 화면
cd app && python3 scripts/build-content.py --check    # 콘텐츠
```

**2026-08-29 부터 CI 가 이 검사들을 대신 돌린다** — `.github/workflows/gates.yml`.
**무엇이 도는지는 `docs/status.generated.md` 가 쥔다** — job·스텝을 코드에서 뽑는다.

**딱 하나는 CI 가 못 돈다 — 위 셋째, 콘텐츠다.** 그 검사는 원장 xlsx 를 읽는데
**원장은 저장소에 없다**(`.gitignore` 의 `*.xlsx`). **콘텐츠를 건드렸으면 손으로 돌려라.**

CI 에 대해 알아 둘 것 셋 —

- **`check:css` 는 `build` 뒤에 돌아야 한다.** `css-class-check.py` 가 빌드 산출 CSS 를
  보는데, `dist` 가 비면 **「건너뜀」을 찍고 그냥 통과한다**(실측). 워크플로가 순서를
  지키고, 그래도 건너뛰면 실패시킨다
- **`parity:activity` 가 쓰는 `tsx` 는 이제 명시된 의존성이다**(2026-08-29).
  전에는 `package.json` 에 없이 **전이 의존성으로 딸려 오는 것에 기대고 있었다** —
  로컬에서는 npx 캐시가 덮어 줘서 안 보였고, **찬 CI 러너였으면 게이트 도중에
  레지스트리에서 내려받았을 것**이다. 버전도 안 잠긴 채로.
- **`biome` 은 0 을 요구하지 않는다.** `biome check src` 는 아직 통과하지 않으므로
  **늘어나지만 않으면** 통과시킨다(기준 60, 2026-08-29). 줄이면 워크플로의 `BASELINE` 도
  같이 내려라

### 목업 대조 — 시각 정본은 목업이다

**구현이 목업과 다르면 목업이 기준이다.**

```bash
cd app && pnpm parity:activity
```

컴포넌트를 정적 HTML 로 그려 `app/src/screens_ref/*.html`(목업에서 캡처한 마크업)과
구조를 비교한다. 갈래는 **활동 + 내비 5(홈 셋 · 교재학습 목록 · 자모 목록) +
VocaShot 5(시작 · 플레이 둘 · 결과 둘) + 게임 17(목록 하나 + 게임 넷 × 화면 넷)** 이다.

**수는 여기 적지 않는다.** 대조 항목과 캡처 수가 따로 움직인다 — 컴포넌트를 대조
목록에 먼저 올리고 목업을 나중에 뜨는 일이 있어서, 그동안 둘이 하나 차이가 난다.
지금 수는 `python3 docs/check_docs.py` 가 첫 줄에 찍는다(`[숫자 주장]` 도 그것으로
비교한다). 대조 목록에 목업이 없으면 `parity:activity` 가 `목업 캡처가 없다` 로 잡는다.

**VocaShot 이 다섯인 것은 상태를 갈라 떴기 때문이다.** 한 화면에 상태가 여럿이면
캡처가 담은 상태만 견줘진다 — 담지 못한 상태는 영영 안 본다. 그래서 플레이는
`4개 중 고르기`와 `직접 입력`을, 결과는 `0점·놓친 단어 없음`과
`신기록·놓친 단어 있음`을 따로 떴다. 그 자리에서 실제 버그 넷이 나왔다(BLOCKERS).
봐주는 차이는 실행할 때마다 같이 찍히므로 무엇을 눈감아 주는지 숨지 않는다.

**홈은 세 상태로 들어가 있다** — 이어서 학습할 것이 없을 때 · 있을 때 · 다시 풀 것이
있을 때(`nav__home__none` · `_resume` · `_review`). 활동 화면들처럼 표시와 데이터를 갈라
`HomeView` 가 props 를 받게 한 뒤에 넣을 수 있었다.

눈으로 볼 것은 Storybook(`pnpm storybook`, 6006)의 두 스토리다 —
"목업 대조"(캡처한 목업)와 "활동 컴포넌트"(우리 것). 나란히 놓고 본다.

### 콘텐츠 생성 — 원장이 정본이다

```bash
cd app && python3 scripts/build-content.py          # 최신 원장으로 다시 만든다
cd app && python3 scripts/build-content.py --check  # 쓰지 않고 차이만 본다
```

`app/src/shared/data/n*.json` 은 **산출물이다. 손으로 고치지 마라** — 다음 생성에서
지워진다. 고칠 것은 원장(xlsx)이다. 자세한 것은 `app/src/shared/data/README.md`.

**정본은 루트의 가장 높은 번호다.** 생성기가 `max()` 로 고른다 — 사람이 고르지 않는다.
옛 판 36개는 `_ledger_superseded/` 로 옮겼다(루트가 66개 항목 중 40개가 xlsx 였다).
**지우지 마라** — 빌드 사슬이 26→27 · 28→29 · 30→31 에서 끊기고 최신 스크립트는
`max()+1` 이라 실행 순서가 기록되지 않는다. 즉 **옛 판은 다시 만들 수 없다.**
v24 가 자모 400행을 날렸을 때 v23 이 있어서 복구했다 — `BLOCKERS.md` §2-b.

생성기는 **따옴표가 홀수인 한글 칸**도 같이 경고한다. 엑셀이 셀 맨 앞의 `'` 를
서식 지시로 읽고 값에서 지우기 때문이다 — 실제로 해설 61개가 그 상태였다.
그 사정과 해설 검수를 어디까지 할지는 `app/src/shared/data/README.md` 에 있다.

### 문서 참조 검사

```bash
python3 docs/check_docs.py
```

문서를 옮기거나 합치거나 절 번호를 바꿨을 때, **그리고 무엇이든 작업을 끝냈을 때**
**"다 고쳤다" 고 믿는 대신 이것을 돌린다.** 하나라도 걸리면 **1 을 낸다.**
**검사 종류도 개수도 여기 적지 않는다** — `check_docs.py` 의 머리말이 목록을 쥐고
개수는 돌 때 스스로 찍는다. 전에 이 줄과 검사기 주석과 실제 구현이 **셋 다 다른 수**였고,
표로 옮겨 적었을 때는 검사가 늘면서 **`앵커` · `사실 중복` · `색인` 셋이 빠진 채 남았다** —
하필 `사실 중복` 이 「같은 수를 두 문서에 적지 마라」를 지키는 검사다.

**걸렸을 때 무엇을 하는지만 여기 적는다** — 그건 코드가 안 알려 준다.

| 걸린 것 | 무엇을 하나 |
|---|---|
| **숫자 주장** | 문서를 고쳐라. **숫자를 맞추려고 코드를 고치지 마라** |
| **사실 중복** | 수를 빼고 주인 문서를 가리켜라. 주인은 `OWNER` 가 정한다 |
| **문구 지뢰** | 그 자리의 "지금 참인 것" 을 읽고 고쳐라.<br>⚠️ **인용과 주장을 가리지 못한다** — 거짓 표현을 예시로 옮겨 적으면 그것도 걸린다. 풀어 써라 |
| **관찰 기준** | **그 문서를 다시 읽어라.** 고칠 것이 없으면 기준 커밋만 지금으로 올린다.<br>**기준만 올리고 안 읽으면 이 검사는 없는 것과 같다** |

> 이 표는 읽기 편하라고 둔 것이고 **정본은 `check_docs.py` 의 머리말**이다.
> 검사를 늘리면 거기를 고친다 — 개수는 실행할 때 스스로 센다.

이 저장소는 문서를 **이름과 절 번호로** 인용한다(절 인용이 **400개가 넘는다**). 그래서 한 곳을
옮기면 조용히 끊어지는 곳이 생긴다 — 실제로 문서를 못 치우고 쌓아 온 이유가 이거였다.

**7~11 은 문서를 합치다 다치고 나서 넣었다.** 1~4 는 "남의 문서를 잘못 부르나" 만 본다.
그런데 절 번호를 다시 붙일 때 정작 위험한 것은 **그 문서 안**이다 — 보이는 번호만 고치고
`id` 와 자기 §N 을 옛 번호로 두면 검사기 넷이 다 통과한다. 실제로 `asis_v1` 에
자기 절 인용 열두 곳과 중복 `id` 다섯 개가 그렇게 남아 있었고, 사람이 눈으로 찾았다.

**10·11 이 같은 병의 가장 큰 조각이었다.** 셸 명세 셋을 `shell_spec_v1` 하나로 합칠 때
**h2 는 0~34 로 다시 매기고 h3 은 옛 번호를 그대로 뒀다.** 인용은 새 번호로 고쳤으니
`§14.1` 을 찾으면 문서 어디에도 없고, 그 자리 제목은 `3.1` 이었다. 게다가 `3.1`~`3.5` 가
행동 층과 구조 층에 **각각 하나씩** 앉아 있었다. **검사 1~9 가 전부 통과하는 동안
§N.M 인용 59곳이 닿지 않았다** — 검사 2 가 `§14.1` 에서 `14` 만 떼어 봤기 때문이다.
h3 33개를 부모 h2 에 맞춰 다시 매겨 풀었다.

**9 는 더 단순한 구멍이었다.** 이 검사기는 본문을 태그 제거해서 읽는다 —
그래서 `href` 안의 파일 이름을 **한 번도 본 적이 없었다.** `shell_spec_v1` 이
옮겨간 문서 셋을 링크한 채로 검사 여덟 개를 다 통과했다. 링크는 사람이 바로
부딪히는 곳이라 이게 제일 아팠다.

**5 가 이 검사기에서 제일 중요하다.** 1~4 는 참조가 끊어졌는지만 보는데, 정작 자주
낡는 것은 **문서에 적힌 수**다. 작업이 진행되면 문서가 저절로 따라오지 않으니까 —
실제로 목업 대조 화면 수가 문서마다 **22 · 24 · 27** 로 갈려 있었고, 끝난 일(홈 셋)이
"남은 일" 로 앉아 있었다. **세는 항목은 늘어난다** — 수를 여기 적지 않는다. `check_docs.py` 의 `OWNER` 가 목록이자 주인 표다.

    목업 대조 화면 수 (활동 + 내비)   활동 컴포넌트 수와 다른 지표다
    정본 문서 수 · _superseded 문서 수

**정확히 맞추게 하는 것과 하한만 보는 것을 가른다.** 문서를 한 줄 고칠 때마다
바뀌는 수(절 인용 총합이 그렇다)를 정확히 맞추게 하면 신호가 아니라 잡일이 된다 —
실제로 한 세션에 네 번 갈렸다. 그런 것은 **"400개가 넘는다" 처럼 하한으로 적고**
검사기도 하한만 본다.

비슷하지만 **다른 지표 셋이 공존한다** — 이식 화면(`masterplan_v3` §15 표 합계) ·
활동 컴포넌트 · 목업 대조. 셋은 세는 단위가 달라 값도 다르다.
**여기 「25 · 22 · 27」로 적혀 있었는데 셋 다 낡아 있었다**(참값은 26 · 23 · 54) —
검사기가 이 산문 꼴을 몰라서 조용히 지나갔다. 그래서 수를 뺐다.
어느 단위인지 밝히는 표는 `CLAUDE.md` 가 쥔다. 검사기는 셋을 구분해서 세므로
맞는 숫자를 틀렸다고 잡지 않는다. 문구를 새로 쓸 때는 `claims()` 의 정규식에 맞춰 쓰거나 거기에 추가한다.

**일부러 어긋나게 둔 곳은 이유를 적어야 통과한다.** 화면 승격은
`docs/screen_promotions.md` 표에, 옛 이름을 부르는 시점 기록은 문서 안에
`옛이름.html → _superseded/` 줄을 두면 봐준다.
눈감아 준 것은 **실행할 때마다 같이 찍힌다** — 목업 대조와 같은 규칙이다.

## 결정이 사는 곳

이 저장소는 **왜 그렇게 했는지를 커밋 메시지에 적는다.** 목업과 다르게 간 곳,
명세와 어긋난 곳, 되돌린 판단이 거기 있다.

```bash
git log --format='%h %s%n%b' -- app/src/components/main/activity
```

목업을 일부러 벗어난 여섯 곳은 `docs/masterplan_v3.html` §16 에 이유까지 적혀 있다.

## 라이선스 — 공개 금지

교재에서 뽑은 문장·어휘·듣기 지문이 **저장소에 추적된 채로 있다**(약 21MB).
`app/src/shared/data/` · `api/seed_data/` · `api/tools/data/` ·
`admin/src/lib/vocashot/vocabData.json` 이 그렇고, `app/src/shared/data/clip.ts` 는
외부 영상 스크립트 329건이다.

이력에 부록 PDF 는 없다 — 195개 커밋을 훑어 확인했다(`.gitignore` 의 반대 주장은
사실이 아니다). 다만 **공개로 돌리면 안 되는 이유는 위 콘텐츠 자체**이므로 결론은
같다. 파일을 지우는 것만으로는 되지 않고 이력을 다시 써야 한다.
