2전체 지도

3이 순서인 이유 — 판단 근거 3가지

  1. 콘텐츠는 사람이 쓰는 것이라 병렬화가 어렵다. 개발은 인력을 붙이면 단축되지만, 급별 문항 저작·검수는 리드타임이 거의 고정이다. 가장 긴 것을 가장 먼저 시작한다.
  2. 콘텐츠 저작은 화면 설계를 기다릴 필요가 없다. "4지선다 어휘 문항"의 데이터 모양만 정해지면 UI가 어떻게 생겼든 문항은 쓸 수 있다. 반대로 화면부터 잡으면 콘텐츠가 통째로 뒤로 밀린다.
  3. 개발은 콘텐츠 없이도 절반이 진행된다. 공통 셸·상태 모델·라우트 정리는 콘텐츠와 무관하다. 구 콘텐츠를 임시로 꽂아 셸을 먼저 검증할 수 있다.

4의사결정 게이트 — 언제 무엇을 정해야 하나

기획서 v0.2.1의 D1~D7을 주제별이 아니라 "무엇을 막고 있는가" 기준으로 재배열했다. 아래 순서대로 닫으면 된다.

G1콘텐츠 착수 게이트지금 · 기획 단독 결정 가능
  • 활동 라인업 확정 — 현행 학습활동 8종 + 게임 5종 중 유지 / 폐기 / 신설. (예: 받아쓰기 폐기, 자모 유지, 롤플레잉 유지…)
  • 활동별 문항 스키마 — 각 활동 1문항이 가진 필드. 예: 어휘 문항 = 표제어 + 뜻(4개 언어) + 정답 + 오답 3개 + 예문 + 음성 여부.
  • 급별 분량 기준 — 과당 활동 수, 활동당 문항 수.

→ 닫히면 즉시 1급 저작 착수. 관련 기존 결정: D3 일부.

G2개발 착수 게이트G1 직후 · 기획+디자인
  • 상태 모델(D2) — 4단계 + 복습 큐 규칙.
  • 라우트·IA 규칙 — 단일 체계 통일.
  • 플레이어 공통 셸 규격(D5) — 헤더·진행바·피드백·결과 화면.
  • 디자인 시스템(D5) — Figma 스타일 가이드를 SoT로 승격.
  • 다국어 적용 범위(D4).

→ 닫히면 Phase 1 셸 개발 착수.

G3B2C 트랙 게이트병렬 · 사업 판단 필요 (리드타임 긺 — 일찍 시작)
  • 무료/유료 경계(D7) — 어디까지 열고 어디부터 잠글 것인가.
  • 인타이틀먼트 방식(D7) — QR = 단순 유입 채널인가, 라이선스 키인가.
  • 가격·구독 형태, PG 벤더 선정·계약, B2C 라이선스 확인(교재 콘텐츠를 개인 판매에 쓸 수 있는지 — 연세 MOU 범위 확인 필요).

→ 결정은 늦어도 되지만 계약·법무 확인은 리드타임이 길다. 착수만 지금.

G4운영·인프라 게이트여유 있음 · Phase 3 전까지

  • 어드민 학습 리포트 범위.
게이트가 없는 작업 — 지금 바로 요청 가능

Phase 0 보안 핫픽스는 어떤 결정도 기다리지 않는다: 무인증 /speech/*·/report 인증 추가, rate limit 복구, 학생 생성 school_code 서버 강제, 빈칸 채우기 오답 저장 버그, VocaShot 참가 QR 도메인 오류, 테스트 라우트 제거. 현행 서비스가 계속 돌고 있으므로 리뉴얼과 무관하게 조치하는 편이 낫다.

6먼저 손댈 것

순서대로 네 가지

  1. 활동 라인업 확정 — 현행 13종(학습 8 + 게임 5)을 놓고 유지/폐기/신설 판정. 역기획서 §4 인벤토리와 현행 목업을 놓고 보면 반나절 작업.
  2. 문항 스키마 초안 — 유지하기로 한 활동별로 "1문항의 필드 목록"을 표로. 이게 저작 양식이 된다.
  3. Phase 0 핫픽스 개발 요청 — 위 목록 그대로 전달. 결정 대기 없음.
  4. B2C 라이선스 확인 착수 — 교재 콘텐츠를 개인 대상 유료 서비스에 쓸 수 있는지. 답이 오래 걸리므로 질문만 지금 던져둔다.

1·2번이 끝나면 콘텐츠 저작을 시작할 수 있고, 그때부터 화면 설계(G2)로 넘어가면 된다.
