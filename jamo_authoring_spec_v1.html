처음에 샘플로 12개만 만들어 보고 접은 활동이다. 라우트가 지워졌고, 콘텐츠 12건도 전부 is_disabled: true다(YK0042 받아쓰기). 지우다 만 것이 아니라 양쪽을 다 정리해서 내린 것이다.

이번에도 넣지 않는다. 교재에는 블록마다 나오지만, 앱에는 이미 쓰기 활동이 2종(단어 읽고 쓰기 · 자음+모음 조합) 있어 필기 연습이 비어 있지 않다. 저작 물량도 48문항이 줄어든다.

반대 방향 유령은 따로 있다. dialog · input_word · make_sentence · write2 4종은 화면만 있고 콘텐츠가 0이다 — 이쪽이 라우트를 지우지 않아 남은 것이다. URL로는 열리지만 앱 안에서 그리로 가는 링크는 0개이고, 들어가면 modules.find(...)가 undefined라 화면이 깨진다. Phase 0에서 지운다.

"한글 연습" 종합 활동 — 여기서 안 맞는다

블록이 끝나면 한글 연습 페이지가 나온다(1과 기준 p20~21). 여섯 활동인데 절반이 앱에 대응물이 없다.

3활동 코드 — sub 값

자모는 menuType='jamo' 하나에 sub로 갈린다. 6종으로 확정한다 — 구 앱에 살아 있는 것과 같다.

구현 사양·API 스키마·개발 명세·G2에 sub는 자모만 1~5로 적혀 있었다. 빠진 것은 write3(자음+모음 조합)다. 네 문서 모두 1~6으로 고쳤다.

구현 사양은 write3를 write와 한 sub로 묶어도 된다고 보았다 — unit이 겹치지 않기 때문이다. 그러나 화면과 인터랙션이 다르고, 묶으면 이어하기 위치와 복습 큐가 뒤섞인다. 나누는 비용은 TINYINT 값 하나다.

6저작 순서

  1. 1과 sub=5(듣고 고르기) 18문항부터 — 선택지형이라 스키마가 가장 단순하고, 이미 n1_word_quiz·n4_blank_question에서 검증된 형식이다. 여기서 컬럼 정의를 확정하고 나머지로 넓힌다.
  2. 1과 sub=3·4(단어 듣고 따라하기 · 읽고 쓰기) — 단어가 겹치므로 같이 쓴다. 교재 블록당 6단어가 두 활동에 그대로 재사용된다.
  3. 1과 sub=1·2(자모 듣고 따라하기 · 쓰기) — 자모 목록이라 기계적이다.
  4. 1과 한글 연습 변환분 → 여기서 §2의 변환 판단을 실제로 적용해 본다.
  5. 1과 전체를 사람이 검토한 뒤 2·3과로 넘어간다.
단어가 활동 사이에 재사용된다 — 이게 저작을 크게 줄인다

교재는 블록마다 같은 6단어를 듣고 따라하기 → 읽고 쓰기 → 듣고 쓰기에 반복해 쓴다. 블록당 단어 6개만 확정하면 세 활동이 함께 채워진다.

1과 기준으로 실제 확정할 단어는 18개다(3블록 × 6). 문항 수 101개에 비해 훨씬 적다.

1과 단어 예시 — 모음1: 이 · 아이 · 오 · 오이 · 에이 · 위 / 자음1: 가게 · 구두 · 노래 · 다리 · 라디오 · 개나리 / 자음2: 모자 · 바지 · 새우 · 지도 · 어머니 · 쇠고기

7저작하며 지킬 것

규칙이유
교재에 없는 단어를 넣지 않는다 자모 과의 단어는 그 시점까지 배운 자모만으로 이루어져 있다. 1과에 ㅊ이 든 단어를 넣으면 읽을 수 없다
선택지는 배운 자모로만 만든다 같은 이유. 오답 선택지도 학습 범위 안이어야 한다 — 교재 p17 예: 다리 / 나리 / 라리는 모두 1과 자음이다
오답은 한 글자만 다르게 교재가 그렇게 되어 있다(그·느·드 · 뮈·뉘·귀). 자모 변별이 목적이므로 차이가 하나여야 무엇을 틀렸는지 드러난다
source_page를 꼭 채운다 나중에 교재와 대조할 때 이게 없으면 다시 찾아야 한다
review_status는 draft로 시작 사람이 검토한 것만 reviewed. 안 본 것을 봤다고 표시하지 않는다

#항목메모
1한글 연습 02·03·04·05 변환안을 받아들일지 §2 권고 — 02·03은 sub=5 선택지, 05는 sub=4 쓰기, 04는 미룸. 교재의 재미 요소가 줄어드는 대가가 있다
2sub=1 자음 결합표를 몇 문항으로 쪼갤지 자음 블록의 듣고 따라하기는 4~5자음 × 10모음 = 40~50칸이다. 한 칸이 한 문항이면 너무 길고, 표 전체가 한 문항이면 진행 표시가 의미 없다. 자음 하나당 한 문항(10칸 묶음)이 적당해 보인다
3발음 평가(STT)를 자모에 켤지 정해짐 켠다. 구 앱이 이미 listen-repeat·listen-repeat2에서 AudioRecorder → POST /stt/convert로 isCorrect와 인식된 단어를 받고 있어 새로 만들 것이 없다.
재시도도 되고 그냥 넘어가는 것도 된다 — 맞을 때까지 막지 않는다. sub=1·sub=3이 해당하고, 두 활동은 문항 전부가 발음이라 채점 집계에서 빠져 결과 화면이 연습 완료로 간다 (구현 사양 §6·§8).
4음성 파일 출처 교재 QR의 MP3를 쓸 수 있는지, 아니면 TTS로 새로 만들지. 라이선스 확인이 필요하다
