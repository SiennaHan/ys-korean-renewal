01문서 지도 — 어느 것이 무엇에 답하나

지도는 이 문서가 아니라 기획서에 있다

renewal_masterplan_v2 §2 덮개 지도 — 영역 × 산출물이고 빈 칸이 곧 빠진 기획이다. 인계 문서는 "2026-08-21 현재 이렇다" 는 시점 기록이고, 지도는 시점과 무관한 상시 자산이라 자리가 다르다. 이 문서가 지도를 들고 있으면 인계가 끝난 뒤에 지도도 같이 낡는다.

이 절이 답하는 것은 "어느 문서가 무엇에 답하나" 뿐이다 — 아래 역할별 목록.

문서가 20개다. 합치기가 진행 중이다 — 아래 절을 봐라.

합치기 — 무엇을 합치고 무엇을 안 합치나

전체 1.5MB · 문서끼리의 절 인용이 400개를 넘는다. 그래서 처음엔 "합칠 수 없다" 고 적었는데 뭉뚱그린 판단이었다. 축을 나눠 재 보니 갈린다.

묶음판정근거 — 실측
목업 넷 activity · nav · shell · vocashot 합친다 :root 공유 변수 39개가 값이 하나도 다르지 않다(같은 디자인 시스템) · @keyframes 이름 충돌 0 · 절 인용 0~2 라 인용이 갈 곳을 잃지 않는다. 클래스 규칙 충돌 15개는 전부 shell 쪽이고 CSS 세대가 한 판 다른 것이라 이름공간으로 감싸면 된다
screens_uiux(게임 절) 따로 432KB(전체의 29%) · <style> 14개 · @keyframes 62개. 앱 DOM 을 뜬 덤프라 어디에 합쳐도 그 문서를 읽을 수 없게 만든다
as-is 셋 home · games · app_asis 합친다 "리뉴얼 전이 어땠나" 하나의 질문에 답한다
G1 둘 activity_lineup · item_schema 합친다 같은 게이트의 산출물 — 활동 라인업과 그 문항 스키마
_superseded/renewal_plan_v0.2 흡수했다 08-21 D1~D7 중 일곱이 이미 다른 문서에서 확정으로 다시 쓰여 있었다 — 같은 결정이 두 곳에 살면서 갈라지는 출처였다. D 이름의 뜻은 renewal_masterplan_v2 §5 의 표가 쥐고, 내용은 각 정의처에 있다
셸 명세 넷 안 합친다 Shell_component_spec_uiux(76) · G2(54) 가 둘이서 절 인용 130개를 진다. 게다가 겹치는 게 아니라 층이다 — 행동 · 구조 · 값 · 순서

합치기가 인용을 깨는지는 문서마다 다르다. 목업은 § 인용이 0~2 라 안전하고, 명세는 130개를 지고 있어 위험하다. 한 덩이로 "합칠 수 있다/없다" 를 말하면 틀린다.

옛 판은 phase1/_superseded/ 로 옮겼다(일곱 개). 그 폴더의 README.txt 가 무엇이 무엇을 대체했는지 적는다. 이 저장소는 _v1 → _uiux 로 판을 올린다.

나머지 문서는 색인에서 찾는다

여기 목록을 두지 않는다. 문서 목록은 phase1/INDEX.md 하나에만 있다 — 전에는 이 절과 README 두 곳에 같은 목록이 있었고, 한쪽만 고쳐져서 문서 수가 25 와 26 으로, 목업 대조 화면 수가 22·24·27 로 갈렸다. 이 절이 스스로 "이 문서가 지도를 들고 있으면 인계가 끝난 뒤에 지도도 같이 낡는다" 고 적어 놓고도 목록을 실어서 생긴 일이다.

색인이 답하는 것 — "기획서" 라 부를 셋이 어떻게 다른가 · 시각 정본 목업 둘 · 셸 명세 넷이 어느 층인가(행동 · 구조 · 값 · 순서) · 화면별 명세 여덟 · 실측과 근거 여섯 · 개발자에게 넘길 묶음 넷. python3 phase1/check_docs.py 가 정본 26개가 모두 색인에 있는지 검사하므로, 문서를 만들고 색인에 안 넣으면 통과하지 않는다.

03목업을 일부러 벗어난 여섯 곳

시각 정본은 목업이다

구현이 목업과 다르면 목업이 기준이다. 이 규칙이 이 저장소의 시각 판단을 전부 지배한다 — 판단이 갈릴 때 코드가 아니라 app/src/mockups/ 를 본다. npm run parity:activity 가 27개 화면을 자동으로 대조한다.

원래 _superseded/handoff_v1 §03 에 있던 규칙을 여기로 옮겼다. 다른 문서가 그 옛 판을 인용하고 있어서 옮길 수 없던 것을 끊었다.

아래 여섯은 그 기준을 알고 벗어난 것이다. 이유가 없으면 다음 사람이 목업대로 되돌린다.

무엇목업구현왜
O/X 라벨들은 문장제시 문장 들은 것은 오디오뿐이고 그 글자는 맞는지 가릴 대상이다. 목업 문구가 틀렸다
문항 사이 이동없음진행 막대를 누른다 도크에 이전을 넣으면 주 버튼이 좁아져 목업과 달라진다. 막대는 5px 이라 누를 자리를 23px 로 넓혔다(생김새는 그대로)

녹음 시작·종료누르면 바로2초 준비 · 1초 마무리 마이크보다 사람이 빨라 첫 음절이 잘린다. 녹음 자체는 누르는 즉시 시작하므로 안내를 무시하고 말해도 잃는 것이 없다

선택지 채점고른 것 하나만틀린 것이 여럿 남는다 맞을 때까지 다시 고르는 기존 동작을 살렸다. 자모 듣고 고르기는 두 번 누르던 것을 한 번으로 바꿨다(다른 활동과 같게)

04그 밖에 오늘 바뀐 것

무엇내용
콘텐츠 v23 반영 앱은 8/6 이식본에 머물러 있었다. 원장(xlsx)과 앱 JSON 을 잇는 것이 없어서다. app/scripts/build-content.py 가 그 일을 한다 — 원장이 정본이고 JSON 은 산출물이다. 들어온 것: 듣기 375문항의 빈 지시문(5개 언어) · 신판 대사 · n4 가 8열→27열 · 플래시카드 12세트 327장 · 문법 234개
자모 경로 이동 /book/chapter/unit/{scene}/{code} → /learn/jamo/*. 이름도 바꿨다 — listen-repeat2 는 2판이 아니라 다른 활동이고 read-write 는 단어 쓰기다. 아직 명세 §4 의 한 라우트 + sub 꼴이 아니다 — 자모 검수 뒤에 합친다. BLOCKERS §2
자모 콘텐츠를 원장으로 자모는 원장 밖(problem.ts)에만 있어 검수 이력이 없고 한국어·영어뿐이었다 — 다른 활동은 5개 언어다. 529문항을 v24 의 n8_jamo 로 옮겼다(컬럼 12→31). 전부 draft — 검수 대기이고 앱은 아직 problem.ts 를 쓴다. jamo_authoring_spec_v1 §4 스키마로는 담기지 않아 실측으로 넓혔다
문서 정리 — 문을 하나로 루트에 문서 여덟이 흩어져 있어서 저장소를 열면 읽을 것이 열 개로 보였다. phase1/ 로 모아 루트에 README.md 와 BLOCKERS.md 만 남겼다. README 를 "처음 30분에 볼 셋" 과 "무엇을 알고 싶으면 어느 문서" 로 다시 썼다 — 31개를 나열하는 대신 물음으로 찾게 했다. handoff_v1 은 네 곳이 §03 을 인용해서 옮길 수 없었다. 그 규칙을 이 문서 §03 이 직접 말하게 하고 인용을 고친 뒤 _superseded/ 로 옮겼다. 같은 방식으로 넷을 더 옮겨 31 → 27 이 됐다. 그러면서 _superseded/ 가 두 가지를 섞어 담고 있다는 것이 드러나 폴더 뜻을 정의했다 — [대체됨](더 새 판이 있다)과 [근거](대체된 게 아니라 다른 문서의 주장을 받치는 산출물)
koreanapi 편입 api/ 로 그대로 들여왔다. 자격증명은 전부 환경변수다. api/IMPORT.md
MY — 게스트 차단 계정 화면이라 게스트는 로그인해야 들어온다. 이걸 넣다가 죽은 경로를 찾았다 — 로그인 화면이 게스트까지 돌려보내서, 로그인 시 게스트 기록을 계정으로 옮기는 migrateGuestData 가 한 번도 쓰이지 않았다
로그인하지 않고 둘러보기 위 차단에 출구가 없었다. MY 를 누른 게스트가 로그인 화면에 갇혀서 로그인 말고는 빠져나올 방법이 없었다. 로그인 버튼 아래에 둘러보기를 붙였다(5개 언어). 게스트로 들어가는 길 자체가 없었던 것도 이때 드러났다 — guestSign() 은 컨텍스트에 올라만 있고 부르는 곳이 없었다. / 스플래시는 토큰이 없으면 로그인으로만 보낸다
토큰 없는 게스트 로그인 checkSign() 이 토큰이 안 와도 성공이라고 답했다. setAccessToken(undefined) 가 문자열 "undefined" 를 저장해서 들어온 것처럼 보이다가 모든 요청이 Bearer undefined 로 나가 조용히 실패한다. 위 버튼이 이 함수를 살아 있는 길로 만들었으므로 같이 고쳤다. 가짜 API 도 실서버처럼 토큰을 내도록 했다
표현클립 다국어 한국어 화면에 영어 안내문이 있었고 신고 사유는 한국어로 박혀 있었다. 12문구를 5개 언어로. 급·과 태그로 클립을 추천하는 안은 접었다 — 10단어 과 하나에 329개 중 221개가 걸려 고르는 데 도움이 안 된다
프로덕션 빌드 수리 배포가 안 되고 있었다. React 19 문제로 보였지만 락파일이 둘이어서 react-router 가 1.170 으로 떠오른 것이었다. 1.136.8 로 고정하고 package-lock.json 을 지웠다. npm 으로 설치하지 마라 — 다시 깨진다. BLOCKERS §1
진행 막대 한 칸 칸이 하나면 늘 꽉 찬 줄이라 어디쯤인지를 말해 주지 못한다. 그리지 않는다
리포트 축 이름 레이더는 번역되는데 바로 아래 칩은 한국어였다. 같은 축을 가리키므로 이름은 앱이 쥔다. 축 이름을 번역하니 레이더가 잘려서 viewBox 를 넓혔다
