v1 을 쓸 때와 무엇이 달라졌나

v1(2026-08-13)은 "실제 생산은 아직 한 줄도 시작하지 않은 지점"이라고 적었다. 그 문장이 이 문서를 합친 이유다 — 8일 만에 콘텐츠·디자인·화면이 다 끝났는데 지도 쪽 문서는 계속 미착수라고 말하고 있었다.

임계 경로가 바뀌었다. v1 은 콘텐츠 저작을 가장 긴 것으로 보고 그것을 먼저 집으라고 했다(§4의 판단 근거 3가지). 그 판단은 맞았고 실제로 그렇게 진행돼 끝났다. 지금 가장 긴 것은 서버다 — DB 2종과 API 7종(신설 5 · 확장 2)이 없어서 화면이 상태를 붙이지 못하고 서 있다. §4 는 그때의 근거를 기록으로 남겨 둔 것이고, 지금 무엇을 먼저 집을지는 §7 먼저 손댈 것을 본다.

3전체 지도 — 트랙과 임계 경로

4이 순서인 이유 — 판단 근거 3가지

  1. 콘텐츠는 사람이 쓰는 것이라 병렬화가 어렵다. 개발은 인력을 붙이면 단축되지만, 급별 문항 저작·검수는 리드타임이 거의 고정이다. 가장 긴 것을 가장 먼저 시작한다.
  2. 콘텐츠 저작은 화면 설계를 기다릴 필요가 없다. "4지선다 어휘 문항"의 데이터 모양만 정해지면 UI가 어떻게 생겼든 문항은 쓸 수 있다. 반대로 화면부터 잡으면 콘텐츠가 통째로 뒤로 밀린다.
  3. 개발은 콘텐츠 없이도 절반이 진행된다. 공통 셸·상태 모델·라우트 정리는 콘텐츠와 무관하다. 구 콘텐츠를 임시로 꽂아 셸을 먼저 검증할 수 있다.

5의사결정 게이트 — 무엇이 닫혔고 무엇이 남았나

아래 게이트는 "무엇을 막고 있는가" 기준이다. 그 재료가 된 주제별 선결 결정 D1~D7 은 원래 renewal_plan_v0.2 에 있었는데, 그 문서를 여기로 흡수하고 폐기본으로 내렸다(2026-08-21) — 여덟 중 일곱이 이미 다른 문서에서 확정으로 다시 쓰여 있어서 같은 결정이 두 곳에 살고 있었다.

선결 결정 D1~D7 — 어떻게 결말났고 지금 어디에 있나

다섯 문서가 D1~D7 로 인용한다. 그 이름의 뜻은 이 표가 쥔다. 결정의 자세한 내용은 "지금 정의처" 열의 문서에 있고, 이 표는 그것을 다시 쓰지 않는다.

7먼저 손댈 것

순서대로 네 가지

  1. 활동 라인업 확정 — 현행 13종(학습 8 + 게임 5)을 놓고 유지/폐기/신설 판정. 역기획서 §4 인벤토리와 현행 목업을 놓고 보면 반나절 작업.
  2. 문항 스키마 초안 — 유지하기로 한 활동별로 "1문항의 필드 목록"을 표로. 이게 저작 양식이 된다.
  3. Phase 0 핫픽스 개발 요청 — 위 목록 그대로 전달. 결정 대기 없음.
  4. B2C 라이선스 확인 착수 — 교재 콘텐츠를 개인 대상 유료 서비스에 쓸 수 있는지. 답이 오래 걸리므로 질문만 지금 던져둔다.

1·2번이 끝나면 콘텐츠 저작을 시작할 수 있고, 그때부터 화면 설계(G2)로 넘어가면 된다.

이게 두 번째다

게임에서 같은 일이 먼저 있었다 — 게임 목업(지금은 screens_uiux 의 게임 절)을 검증용 산출물로만 다루고 앱에 옮기는 일을 구현 목록에 넣지 않았다. 그때 원인을 "목업이 덧씌우는 층이라서"로 적었는데, 이번엔 목업을 아예 열지 않았다. 원인이 다르고, 둘 다 같은 결과를 냈다.

12계획

0단계 — 읽기 코드 쓰기 전

  1. 활동 20화면을 화면별로 DOM 구조·실측 수치로 정리한다. 소스 빌더 함수를 읽는다(브라우저 순회는 느리다).
  2. 나머지 목업(screens_uiux 의 홈·목록·VocaShot 절 · shell · game)도 같은 방식으로 훑는다.
  3. 정리 결과를 먼저 보여 드린다 — 구조를 제대로 이해했는지 확인받고 나서 코드를 쓴다.
  4. §3 의 어긋남 목록을 확정한다. 특히 진행바 정오답 표시 여부.

1단계 — 목업 CSS 를 앱으로

Tailwind 유틸리티로 숫자를 다시 옮겨 적는 방식이 이번 실패의 원인이었다. 목업이 이미 클래스와 CSS 로 디자인을 들고 있으니 그것을 정본으로 가져온다.

  • 목업의 CSS 를 앱 스타일시트로 이관 — 색은 tokens.css 의 semantic 으로 치환
  • 클래스 이름을 목업과 같게 쓴다. 그래야 대조가 눈으로 된다
  • Storybook 스토리 = 목업 화면과 1:1. 다른 상태를 새로 상상하지 않는다

2단계 — 컴포넌트

순서대상서버 필요
1appbar · progress-wrap · footer/dock — 전 화면 공통없음
2choice · chip-opt — 선택지 두 종류없음
3problem-card(instruction · stimulus) · feedback-slot없음

5ActivityShell — 상태·진행·종료2번

3단계 — 게임

게임은 기획·콘텐츠가 닫혔고 디자인 이식만 남았다. 활동 셸과 독립이라 병행할 수 있다.

  • 봄소풍 · 서울 퍼즐 — 클래스 주입 0건이라 CSS 만 옮기면 된다
  • 카드 마스터 — 클래스 36개를 JSX 에 심는다
  • 조사 스나이퍼 — 과녁으로 새로(ps-range · ps-reticle · ps-impact-*). 낙하는 없어졌다
  • VocaShot — 개인 플레이 화면과 기계를 같이

막혀 있는 것

  • koreanapi 를 저장소로 들일지 — 1·2번이 서버라 이게 결정돼야 5·8번이 완결된다
  • 진행바 정오답 표시 — 문서와 목업이 어긋난다(§3)
  • 프로덕션 빌드가 깨져 있다 — React 18/19 use import 불일치. 내 변경 전부터 있던 것이고 아직 아무도 안 고쳤다
일하는 방식을 바꾼다

화면을 만드는 작업은 목업을 먼저 열고 시작한다. 숫자 명세는 근거를 찾을 때만 본다 — 정본이 아니기 때문이다. 어긋나면 목업을 따르고 문서 쪽을 고친다.
