[게임 다섯 — 디자인 인계]

앞서 학습 활동 19화면과 홈·교재학습·자모를 네가 확정했다. 이번은 게임 탭이다.
새로 그리는 게 아니라 **이미 배포돼 있는 화면의 퀄리티를 올리는** 일이다.


■ 먼저 — 목업 말고 앱을 띄워서 봐라

내가 게임 화면을 손으로 옮긴 목업을 만들었다가 **버렸다**.
앱을 실제로 띄워 보니 빠진 게 너무 많았다 —

  봄소풍     CSS 로 그린 소풍 풍경(벚나무·잔디·돗자리·친구)이 화면마다 이어진다
  서울 퍼즐   CSS 로 그린 서울 지도(한강 물결·녹지·격자·지명)가 있다
  카드 마스터 결과의 등급이 큰 글자 하나, 통계는 세로 목록
  조사 스나이퍼 급마다 테두리·글자 색이 다르다

내 목업에는 앞의 둘이 **통째로 없었다**. 코드를 읽어서는 안 보인다.
_superseded/ 로 옮겨 뒀으니 참고만 하고, 아래대로 직접 띄워 봐라.


■ 띄우는 법 (10분)

  1) 의존성
     cd korean-master/korean-master && npm install

  2) .env 를 만든다 — **여덟 개를 다 채워야 한다**
     PUBLIC_KOREAN_API_URL=http://127.0.0.1:8799
     PUBLIC_SPEAK_API_URL=http://127.0.0.1:8799
     PUBLIC_WRITE_API_URL=http://127.0.0.1:8799
     PUBLIC_RES_URL_ROOT=
     PUBLIC_APPSYNC_ENDPOINT=http://127.0.0.1:8799/graphql
     PUBLIC_APPSYNC_REGION=ap-northeast-2
     PUBLIC_APPSYNC_API_KEY=mock
     PUBLIC_QR_WEB_REDIRECT_URL=/

     하나라도 빠지면 rsbuild 가 치환을 안 해서
     "process is not defined" 로 **흰 화면**이 된다. 여기서 한참 헤맸다.

  3) 가짜 API 를 띄운다 (게임 콘텐츠만 있으면 된다)
     python3 phase1/game_mockapi.py   — seed_data 의 JSON 을 그대로 내보낸다(8799 포트).
     엔드포인트 아홉 개: /game-content/{spring-picnic,particle-sniper,card-sort,seoul-puzzle,vocashot}/...
     응답 형식은 { result, code, message, data } 다.

  4) npm run dev  → http://localhost:3000

  5) 로그인 화면이 뜨면 — **로그인하지 말고** 콘솔에서
     localStorage.setItem('koreanAccessToken','local-dev-mock')
     게이트는 /main 레이아웃의 isSignedIn = !!getAccessToken() 하나다.

  6) 게임 라우트로 바로 간다. 라우트에 인증 가드가 없다.
     /main/game
     /main/game/card-sort  /main/game/particle-sniper
     /main/game/spring-picnic  /main/game/seoul-puzzle

  ※ 화면 전환에 framer-motion 페이드가 있어서 캡처가 흐리게 잡힌다.
    콘솔에서 애니메이션을 끄고 찍어라 —
    document.head.insertAdjacentHTML('beforeend',
      '<style>*,*::before,*::after{animation:none!important;transition:none!important}</style>')


■ 알아 둘 것 — 손대는 비용이 게임마다 다르다

  조사 스나이퍼   Tailwind + 인라인 혼합   (className 71 / style 42)
  봄소풍          별도 CSS 파일            (spring-picnic.css 1070줄, 변수 기반)
  서울 퍼즐       거의 전부 인라인          (style 140 / className 4)
  어휘 카드 마스터 전부 인라인              (style 67 / className 0)

봄소풍은 CSS 변수(--pk, --pkb, --pu …)만 바꿔도 많이 움직인다. 넷 중 가장 싸다.
카드 마스터와 서울 퍼즐은 컴포넌트 안의 스타일 객체를 직접 고쳐야 한다.


■ 팔레트가 제각각이다

  VocaShot        어둡다  #020617
  조사 스나이퍼    어둡다  #060612   (급마다 강조색이 다르다)
  어휘 카드 마스터  어둡다  #060612   (갈래마다 색이 다르다)
  서울 퍼즐        밝다   #f2f4f7 + navy 헤더
  봄소풍          밝다   #fff0f5 분홍
  목록            밝다   #F9FAFC

셋이 어둡고 둘이 밝다. **통일할지는 정해지지 않았다** — 게임마다 성격이 달라서
그대로 두는 것도 답이다. 네 판단을 듣고 싶다.


■ 손대도 되는 것

여백 리듬, 모서리 반경, 그림자, 타이포 위계, 아이콘, 전환·애니메이션 마감,
버튼 눌림 상태, 어두운 배경의 층 구분(지금 #060612 하나로 납작하다).


■ 손대지 마라 — 규칙이 걸려 있다

- 조사 스나이퍼의 **문항 낙하**. 타이머에 맞춰 위에서 아래로 내려온다.
  바닥의 GROUND 선이 "시간이 다 됐다"를 뜻한다. 연출이 아니라 규칙이다.

- 어휘 카드 마스터의 **판 60초 타이머**(상단 4px, 10초 남으면 빨강)와
  **갈래 색**. 갈래 색은 card_sort_categories 데이터가 들고 있다
  ({ "직업": "#4A9EFF" }) — 화면에서 못 바꾼다. 콘텐츠를 고쳐야 한다.
  갈래가 4개 이상이면 글자가 13→11 로 줄어드는 규칙도 있다.

- 서울 퍼즐의 **[이름] 치환**. 이름 끝 받침에 따라 이에요/예요가 갈린다.

- 봄소풍의 **숫자 크게**(3.2rem). 답이 되는 숫자를 크게 보여주는 게 이 게임의 핵심이다.
  선택지가 세로 1열 왼쪽 정렬인 것도 의도다 — "네 명"처럼 길이가 들쭉날쭉해서
  2열로 놓으면 줄이 어긋난다.

- 봄소풍·서울 퍼즐의 **CSS 일러스트**. 이미지가 아니라 div 로 그린 것이다.
  다시 칠할 때 통째로 갈아엎기 전에 한 번 물어봐 줘.


■ 목록 화면 — 둘째 줄이 한 자리다

카드 다섯이 지금 통째로 복사돼 있고 **진행 상태가 하나도 안 보인다**.
설명 줄 자리에 진행이 있으면 진행을, 없으면 설명을 넣는다. 카드 높이 80 유지.

  VocaShot     2급 최고 210점
  봄소풍       민수 · 2단계까지 했어요
  서울 퍼즐    12곳 중 5곳 다녀왔어요
  카드 마스터  3급 5과 최고 2,140점
  조사 스나이퍼 (아직 안 해봄 → 설명이 남는다)

phase1/gamelist_mockup_v1.html 에 그려 뒀다(이건 단순 정적 화면이라 신뢰해도 된다).
활동 목록·홈 카드와 같은 "한 자리, 내용만 교체"다.
진행 단위가 게임마다 달라서(급 · 장소 · 친구×단계 · 레슨) 공통 숫자를 못 만든다.


■ 문구가 i18n 으로 빠진다 — 레이아웃에 영향이 있다

네 게임 다 t() 를 **한 번도 부르지 않고** 한글이 박혀 있다(약 128개).
목록은 번역되는데 들어가면 한국어가 된다 — 베트남 학습자가 "Đoán từ" 를 눌러
들어가면 "급수를 선택하세요"를 만난다.

phase1/game_ui_i18n_v1.ts 에 다섯 로케일 78키 초안을 넣어 뒀다.
빼면서 **글자 길이가 언어마다 달라진다** —

  "다시 도전"        → "Play again" / "もう一度" / "再玩一次" / "Chơi lại"
  "급수를 선택하세요"  → "Choose a level to start" / "Hãy chọn cấp"

버튼·배지·탭 라벨을 **고정 폭으로 잡지 말고** 늘어날 여지를 두고 그려 줘.
말줄임을 쓸 자리라면 어디를 자를지도 정해 주면 좋겠다.

번역하지 않는 것 — 급·과 라벨(2급 · 5과)은 교재의 이름이고,
GROUND · MISS · XP · COMBO 는 이미 영문이라 그대로 둔다.


■ 같이 진행되는 것 (디자인과 무는 부분만)

- 다섯 게임 다 **점수를 저장**하게 된다. 지금은 둘만 한다.
  → 목록의 진행 표시와 결과 화면의 "최고 점수" 자리가 필요해진다.
- 점수 규칙이 **처음 맞힌 것만** 세는 쪽으로 통일된다.
  → 결과 화면에서 "맞힘"과 "점수"가 다른 값이 된다. 둘을 같이 보여줘야 한다.
- 서울 퍼즐은 오답에 정답을 통째로 보여주던 것을 고친다.
  → 오답 피드백 영역의 내용이 바뀐다.

자세한 이유는 phase1/games_polish_v1.html 에 게임별로 적혀 있다.


■ 이번에 배운 것

처음엔 코드를 읽고 목업을 손으로 그렸다. 봄소풍 선택지를 2열로,
카드 마스터 슬롯을 2열 사각으로, 조사 스나이퍼를 정적인 문제로 그렸는데
실제로는 각각 세로 1열 / N열 한 줄 / 낙하형이었다.

그다음엔 JSX 를 스크립트로 변환했다(값은 정확해졌지만
조건부 렌더와 .map 함수 본문은 못 폈다).

결국 **앱을 띄우는 게 답이었다.** 띄우자마자 카드 마스터의 진짜 버그도 나왔다
(기본값으로 바로 START 하면 덱이 빈다 — startGame 의 useCallback 이
vocab 을 의존성에 안 넣었다). 코드만 읽어서는 못 찾았을 것이다.
