[게임 다섯 — 디자인 인계]

앞서 학습 활동 19화면과 홈·교재학습·자모를 네가 확정했다. 이번은 게임 탭이다.
새로 그리는 게 아니라 **이미 배포돼 있는 화면의 퀄리티를 올리는** 일이다.


■ 목업 — phase1/game_screens_v1.html

**배포된 화면 14개를 렌더된 DOM 그대로** 뽑아 넣었다.
앱을 로컬에서 띄우고, 각 화면에서 outerHTML 과 스타일시트를 통째로 캡처했다.
**내가 옮겨 적은 값은 하나도 없다.**

  목록
  어휘 카드 마스터   레벨 선택 · 인트로 · 게임 중 · 결과
  조사 스나이퍼     급 선택 · 과 선택 · 게임 중
  봄소풍           타이틀 · 미션 선택 · 문항
  서울 퍼즐        지도 · 도착 대화 · 문장 조립

고치는 곳은 파일 안의 두 군데다 —
  APP_CSS   앱의 스타일시트 전부(159KB). 여기가 곧 앱의 CSS 다.
  SCREENS   각 화면의 마크업.

APP_CSS 는 **14화면에서 모은 CSS 를 규칙 단위로 합친 것**이다.
rsbuild 가 라우트별로 CSS 를 쪼개서, 화면마다 실린 스타일시트가 다르다 —
목록 화면에는 spring-picnic.css 가 아예 없다. 그래서 전부 합쳐야 한다.
어느 화면을 고쳐도 다른 화면에 같이 반영된다 — 실제 앱과 같은 성질이다.
화면은 iframe 안에서 그린다(앱 CSS 가 벤치를 침범하지 않게).

인라인 style= 로 박힌 값이 많다(카드 마스터·서울 퍼즐). 그건 SCREENS 쪽에서 고쳐야 한다.
봄소풍은 spring-picnic.css 의 변수(--pk, --pkb, --pu …)를 쓰므로 APP_CSS 에서 고치면 된다.


■ 한 번 틀렸던 것 — CSS 를 합치는 방법

처음엔 목록 화면의 스타일시트만 넣었다. 그러면 봄소풍의 .spg,
서울 퍼즐의 .sp-loc-card, 카드 마스터의 holographic 규칙이 **통째로 빠진다**.
마크업은 있는데 CSS 가 없어서 원본 모양이 안 나온다.

합칠 때도 줄 단위로 중복을 없앴다가 @media 블록이 조각나
중괄호 43개가 안 닫히고 CSS 가 통째로 무시됐다.
지금은 **중괄호 깊이를 세어 규칙 단위로** 합쳤다(287규칙, 균형 0).


■ 목업에서 알아 둘 것 셋 (CSS 전수 확인함)

1) **폰트가 안 뜬다.** 앱은 Exo 2 와 Pretendard 를 @import 로
   Google Fonts · jsDelivr 에서 받는다. 목업에선 외부 요청이 막혀
   **대체 글꼴로 보인다**. 타이포를 판단할 땐 이걸 감안해라 —
   숫자·점수는 원래 Exo 2(700/900)다.

2) **--app-width 는 캡처 범위 밖에서 정해진다.** app-layout 이
   래퍼에 인라인으로 넣는 값이라 캡처에 안 들어왔다.
   봄소풍의 .spg 가 max-width: var(--app-width, 375px) 라
   그대로 두면 390 폭에서 양옆 8px 씩 흰 띠가 남았다.
   목업 iframe 에 --app-width: 100% 를 줘서 기기 폭을 꽉 채우게 했다.
   **실제 앱에서도 셸 폭이 375 보다 넓으면 같은 여백이 생긴다** — 알고 있어라.

3) 클래스 커버리지는 확인했다. 마크업이 쓰는 클래스 197개 중
   **규칙 없는 것 0개**(SVG className 인공물 2개 제외).


■ 처음엔 내가 손으로 옮겼다가 버렸다

코드를 읽고 목업을 그렸더니 거의 다 틀렸다 —
봄소풍 선택지를 2열로, 카드 마스터 슬롯을 2열 사각으로, 조사 스나이퍼를
정적인 문제로 그렸는데 실제로는 세로 1열 / N열 한 줄 / 낙하형이었다.
그다음엔 JSX 를 스크립트로 변환했는데, 조건부 렌더와 .map 함수 본문을 못 폈다.

**그리고 결정적으로 — 봄소풍의 소풍 풍경과 서울 퍼즐의 서울 지도가 통째로 빠져 있었다.**
둘 다 이미지가 아니라 div 로 그린 CSS 일러스트다. 코드를 읽어서는 안 보인다.
그 목업들은 _superseded/ 로 옮겼다.

■ 손대지 마라 — 규칙이 걸려 있다

- 조사 스나이퍼의 문항은 **고정 위치**다. 12초 제한은 상단 타이머만 전달한다.
  과녁·조준경은 현재 문항에 초점을 모으는 장식이고, 탄착은 답을 고른 직후의 피드백이다.
  문항을 이동시키거나 GROUND 선을 두지 않는다. 낙하 규칙은 VocaShot에만 있다.

- 어휘 카드 마스터의 **판 60초 타이머**(상단 4px, 10초 남으면 빨강)와
  **갈래 색**. 갈래 색은 card_sort_categories 데이터가 들고 있다
  ({ "직업": "#4A9EFF" }) — 화면에서 못 바꾼다. 콘텐츠를 고쳐야 한다.
  갈래가 4개 이상이면 글자가 13→11 로 줄어드는 규칙도 있다.

- 서울 퍼즐의 **[이름] 치환**. 이름 끝 받침에 따라 이에요/예요가 갈린다.

- 봄소풍의 **숫자 크게**(3.2rem). 답이 되는 숫자를 크게 보여주는 게 이 게임의 핵심이다.
  선택지가 세로 1열 왼쪽 정렬인 것도 의도다 — "네 명"처럼 길이가 들쭉날쭉해서
  2열로 놓으면 줄이 어긋난다.

- 봄소풍·서울 퍼즐의 **CSS 일러스트**. 이미지가 아니라 div 로 그린 것이다.
  다시 칠할 때 통째로 갈아엎기 전에 한 번 물어봐 줘.


■ 목록 화면 — 둘째 줄이 한 자리다

설명 줄 자리에 진행이 있으면 진행을, 없으면 설명을 넣는다. 카드 높이 80 유지.

  봄소풍       민수 · 2단계까지 했어요

  카드 마스터  3급 5과 최고 2,140점
  조사 스나이퍼 (아직 안 해봄 → 설명이 남는다)

phase1/gamelist_mockup_v1.html 에 그려 뒀다(이건 단순 정적 화면이라 신뢰해도 된다).
활동 목록·홈 카드와 같은 "한 자리, 내용만 교체"다.
진행 단위가 게임마다 달라서(급 · 장소 · 친구×단계 · 레슨) 공통 숫자를 못 만든다.


■ 문구가 i18n 으로 빠진다 — 레이아웃에 영향이 있다

네 게임 다 t() 를 **한 번도 부르지 않고** 한글이 박혀 있다(약 128개).
목록은 번역되는데 들어가면 한국어가 된다 — 베트남 학습자가 "Đoán từ" 를 눌러
들어가면 "급수를 선택하세요"를 만난다.

phase1/game_ui_i18n_v1.ts 에 다섯 로케일 78키 초안을 넣어 뒀다.
빼면서 **글자 길이가 언어마다 달라진다** —

  "다시 도전"        → "Play again" / "もう一度" / "再玩一次" / "Chơi lại"
  "급수를 선택하세요"  → "Choose a level to start" / "Hãy chọn cấp"

버튼·배지·탭 라벨을 **고정 폭으로 잡지 말고** 늘어날 여지를 두고 그려 줘.
말줄임을 쓸 자리라면 어디를 자를지도 정해 주면 좋겠다.

번역하지 않는 것 — 급·과 라벨(2급 · 5과)은 교재의 이름이고,
MISS · XP · COMBO 는 이미 영문이라 그대로 둔다.


■ 같이 진행되는 것 (디자인과 무는 부분만)

- 다섯 게임 다 **점수를 저장**하게 된다. 지금은 둘만 한다.
  → 목록의 진행 표시와 결과 화면의 "최고 점수" 자리가 필요해진다.
- 점수 규칙이 **처음 맞힌 것만** 세는 쪽으로 통일된다.
  → 결과 화면에서 "맞힘"과 "점수"가 다른 값이 된다. 둘을 같이 보여줘야 한다.
- 서울 퍼즐은 오답에 정답을 통째로 보여주던 것을 고친다.
  → 오답 피드백 영역의 내용이 바뀐다.

자세한 이유는 phase1/games_polish_v1.html 에 게임별로 적혀 있다.
