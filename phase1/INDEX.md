# 문서 색인 — 어느 문서가 무엇에 답하나

**이 저장소에서 문서 목록은 여기 하나뿐이다.** 전에는 README 표와
`masterplan_v3` §14 두 곳에 같은 목록이 있었고, 그래서 한쪽만 고쳐지는 일이
반복됐다(문서 수가 25 와 26 으로 갈렸고, 목업 대조 화면 수는 22·24·27 로 갈렸다).
목록을 늘리지 마라 — 다른 문서는 **여기를 가리키기만** 한다.

`python3 phase1/check_docs.py` 가 **정본·확인용 HTML 19개가 모두 이 색인에 있는지** 검사한다.
**이 문서가 문서 수·폐기본 수·인계 메모 수의 주인이다** — 다른 문서에 그 숫자를 적지
마라(`[사실 중복]` 이 잡는다). 화면 수의 주인은 `README.md` 다.
문서를 새로 만들면 여기 한 줄을 넣어야 검사기가 통과한다.

> 여기 있는 것은 **문서 목록**이다. **무엇이 비었나**(영역 × 산출물, 빈 칸이 곧
> 빠진 기획)는 `masterplan_v3.html` **§2 덮개 지도** 에 있다 — 그것도 한 곳뿐이다.

## 3. 셸 명세 넷 — 층이 다르다

넷이 겹쳐 보이지만 **겹치지 않는다.** 같은 셸을 네 층에서 말한다.
값을 대조해 봤고 어긋난 곳이 없다. 하나를 열었을 때 나머지 셋에 무엇이 있는지는 이 표로 안다.

| 층 | 어디 | 무엇 |
|---|---|---|
| **행동** | `shell_spec_v1.html` §0~§10 | 상태 머신 · 라우트 통일 · 정상 흐름 밖의 화면 · 접근성 · 용어. **가장 많이 인용된다** |
| **구조** | 같은 문서 §11~§20 | 컴포넌트별 상태와 슬롯 · 320 폭 실측 · 활동 8종이 어느 슬롯에 무엇을 넣나. **셸 결정 `S1`~`S3` 의 정의처**(§19.0) |
| **값** | 같은 문서 §21~§34 | 토큰 · 타이포 · 색 · 간격 · 채점·피드백 수치 · 검증 |
| **순서** | `dev_spec_v1.html` | 최초 구현 순서와 현재 필드 계약 · 검증 기준. 현재 우선순위는 `BLOCKERS.md` §0 |

> `S3` 가 두 가지를 가리킨다 — `shell_spec_v1` 에서는 **셸 결정 3번**,
> `access_and_pricing_v1` 에서는 **AWS S3** 다. `S1`~`S3` 는 기획서의 `D1`~`D7` 과 다른 계열이다.

**셸 밖까지 보려면 [`../DESIGN.md`](../DESIGN.md) 다.** 위 `값` 층은 *학습 활동 셸의
명세*고, DESIGN.md 는 **전 화면군(활동·내비·인증·표현클립·레거시 교재·MY)의 현황**을
코드에서 재어 적은 것이다 — 무엇이 갈렸고 무엇을 정해야 하는지가 §8 에 표로 있다.
값이 둘에서 갈리면 `shell_spec_v1` 이 이긴다. 게임 다섯은 DESIGN.md 범위 밖이다.

**어드민 쪽 위험은 `admin_spec_v1.html` §06 에 모아 두었다** — 학교 코드 편집이 학생을 조용히 고아로 만드는 것, 탈퇴 뒤 남는 코드 사용 기록, 그리고 **어드민에 게이트가 없는 것**(타입 검사가 통과하지 않고 빌드가 유틸리티 CSS 를 내지 않는다). 실행 목록에 넣을지는 기획자가 정한다.

`developer_tasks.md`만 읽어도 일을 나눌 수 있어야 한다. 나머지 문서는 작업 카드가
가리키는 부분의 **근거와 필드 계약**이며, 개발자가 과거 기록 전체를 읽고 현재 과업을 추측하게 하지 않는다.

외부 API 는 이미 붙어 있는 것과 새로 붙일 것이 갈린다 —
붙어 있는 것은 `api/TUTORUS_INTEGRATION.md`(발음평가·비원어민 STT) · OpenAI · Gemini TTS,
새로 필요한 것은 **메일 발송(SES 등)** 과 **결제**다. QR 홈 착지·표현클립 신고·
음성 보관 운영·콘텐츠 게이트·CI와 관측까지 포함한 전체 범위는 인계서가 맡는다.

## 옛 판은 어디에

그 뒤 옮겨진 파일은 맨 위 머리말이 어디로 갔는지 적는다.
