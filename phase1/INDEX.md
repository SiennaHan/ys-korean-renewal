## 3. 셸 명세 넷 — 층이 다르다

넷이 겹쳐 보이지만 **겹치지 않는다.** 같은 셸을 네 층에서 말한다.
값을 대조해 봤고 어긋난 곳이 없다. 하나를 열었을 때 나머지 셋에 무엇이 있는지는 이 표로 안다.

## 6. 개발자에게 넘길 묶음 — 백엔드와 외부 API

지금 목표는 **화면은 내가 마무리하고, 개발자는 서버와 외부 API 만** 확실히 해서
배포하는 것이다. 그 범위에 필요한 것은 **셋 + 문 하나**뿐이다. 나머지는 넘기지 않는다.

| 순서 | 문서 | 왜 필요 |
|---|---|---|
| 1 | [`../BLOCKERS.md`](../BLOCKERS.md) **§6 · §7** | 서버 작업은 크게 진행됐다(권한 판정 · 복습 큐 · 자체 회원가입 · 문의) — **남은 것은 결제 · 메일 발송 · 표현클립 신고**다. **여기가 실제 작업 목록이다**.<br>**§6-e 는 순서를 지켜야 한다** — 컬럼을 먼저 늘리면 익명 한 사람이 영상을 전원에게서 지우는 동작이 살아난다 |
| 2 | `dev_spec_v1.html` | DB 신설 2종(`ko_activity_state` · `ko_review_queue`) · API · 검증 기준 ·<br>요청·응답 필드(§10~§16). **§16 의 남은 둘에 답을 받아야 한다**(나머지 둘은 정해졌다) |
| 3 | `access_and_pricing_v1.html` | 권한 판정 · 결제. **§07 여섯 물음이 다 해소됐다 (2026-08-26)** — 구독으로 정했고 `ko_entitlement` 는 기간 단위다.<br>**남은 것은 가격 하나** · PG 계약 · B2C 라이선스다 — 주기는 **월**로 정했다(2026-08-26) |

**넘기는 문서는 여전히 셋이다.** 표현클립 신고도 새 문서를 만들지 않고
`BLOCKERS.md` **§6-e** 에 넣었다 — 거기가 실제 작업 목록이기 때문이다.
왜 그렇게 정했는지(신고는 숨기지 않고 하위로 · 단위는 구간)가 필요하면
`clip_spec_v1.html` §05 의 6번이 근거이고, **넘길 때 같이 보낼 필요는 없다.**

외부 API 는 이미 붙어 있는 것과 새로 붙일 것이 갈린다 —
붙어 있는 것은 `api/TUTORUS_INTEGRATION.md`(발음평가·비원어민 STT) · OpenAI · Gemini TTS,
새로 필요한 것은 **메일 발송(SES 등)** 과 **결제**다(둘 다 BLOCKERS §7 · §6).

## 옛 판은 어디에

정본이 아닌 43개는 `_superseded/` 에 있다. 그 폴더의 `README.txt` 가 항목마다
**[대체됨]**(더 새 판이 있다)인지 **[근거]**(다른 문서의 주장을 받치는 산출물)인지 적는다.

인계 메모 셋(`*_handoff_note.txt`)은 **시점 기록**이다. 본문은 당시 그대로 두고,
그 뒤 옮겨진 파일은 맨 위 머리말이 어디로 갔는지 적는다.
