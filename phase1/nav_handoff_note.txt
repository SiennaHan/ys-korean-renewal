■ 정한 것 셋과 그 이유

1) 활동 목록 항목은 높이 46을 유지하고, 오른쪽 한 자리를 상태에 따라 갈아 낀다.

   미학습    → 비운다
   진행 중   → "진행 중" (파랑)
   완료      → 완료 배지 (초록)
   복습 권장 → 완료 배지 + 복습 N (주황)

   넷이 동시에 나타나지 않으므로 한 자리로 된다. 320에서도 제목이 안 잘리는 걸 확인했다.

   "미학습은 비운다"가 중요하다. 0/9는 정보가 아니고, 표기가 없는 것이 곧 미학습이다.

   ※ 처음에는 진행 중 자리에 3 / 9 를 넣었다가 뺐다. 아래 "진행 표기" 항 참고.

2) 자모는 지금처럼 따로 둔다.

   확인해 보니 자모 목록 화면이 이미 있다 — components/main/course-list/jamo.tsx 217줄.
   routes/jamolist.tsx 는 9줄짜리 빈 스텁("Hello /jamolist!")이라 헷갈리기 쉽다.

   구조가 과 → unit → 활동 3층으로 교재학습(과 → 활동 2층)보다 한 겹 깊다.
   unit 카드에 음절 칩 28이 가로로 붙는다.
   상태 표기는 활동 항목에만 붙인다 — unit은 학습 단위가 아니라 묶음이다.

3) 홈의 오늘 할 일은 한 자리에 세 갈래를 갈아 낀다.

   resume → 이어서 학습하기 + 진행 위치 (▶)
   review → 다시 풀 문항 N개 (↻)
   none   → 학습 시작하기 (📖)

   지금 앱도 "이어할 것 없으면 학습 시작하기로 바뀌는" 방식이라 그걸 그대로 쓴 것이다.
   오늘 할 일이 하나로 보이는 게 이 카드의 목적이라, 두 카드로 나누지 않았다.


■ 진행 표기 — 목록에는 숫자를 쓰지 않는다 (확정)

숫자를 낼 데이터는 있다. getLearningProgress 가 활동별 p.total(학습한 문항 수)을 주고,
구 앱의 완료 판정이 바로 p.total >= totalQuestions 다. 그래서 n / N 을 넣고 그려 봤다.

보기가 나빴다. 3 / 5 와 12 / 45 가 한 줄씩 늘어서면 분모가 서로 달라 비교가 안 되는데
눈에는 자꾸 걸린다. 게다가 둘은 결국 같은 상태(진행 중)다.
같은 것을 다르게 보여주고 있었다.

목록에 보이는 것은 "진행 중" 하나로 맞춘다.
숫자는 버리지 않고 데이터로 갖고, 홈 이어하기 카드와 활동 안 진행바에서만 쓴다.
둘 다 한 화면에 하나만 나오는 자리라 나란히 놓이는 문제가 없다.
API 는 그대로 숫자를 내려주고, 목록 UI 만 상태로 렌더한다.

먼저 나왔던 "분모가 1이면(미션 대화 0/1) 숫자를 쓰지 않는다"는 예외는
목록 전체가 글자가 되면서 없어졌다. 규칙이 하나가 된 것이 부수 이득이다.

이건 표로만 정했으면 안 보였다. 일곱 활동을 한 화면에 늘어놓아야 보인다.
구조를 먼저 그려 본 이유가 이거다.

- 홈은 720 안에 다 들어간다(내용 693). 덩어리를 키우면 주간 활동 차트가 접힌다.

- 자모 unit 카드의 음절 칩은 가로 스크롤이어야 한다. 모음 1은 10자다.

홈이 같은 셸에서 앱바 없이 이미 정상 동작한다는 것이다(pt 18~20 만으로 시작).
env(safe-area-inset-top) 이 저장소에 없다는 것은 그걸 뒷받침하는 정황일 뿐이다.

■ 최상단 여백은 손대지 마라 — 이미 맞아 있다

내가 앞서 "7px 어긋난다"고 적었는데 틀렸다. 재 봤다.

                요소 상단   콘텐츠 상단   글자 상자 상단   잉크 상단
  교재 탭        11         16           18              19.95     (14 / lh 20)
  홈 인사        18         18           18              19.95     (14 / lh normal)

.tab2 가 line-height:20 을 갖고 있어서 반쪽 여백 (20-16)/2 = 2 가 그 차이를 정확히 먹는다.
글자 상자와 잉크 상단이 둘 다 같은 자리다.

확인 — 홈 인사에 line-height:20 을 강제로 주면 글자 상자가 18 에서 20 으로 내려간다.
지금 둘이 18 에서 만나는 게 그 반쪽 여백 덕이라는 뜻이다.
그래서 스트립을 11 -> 13 으로 올리면 탭이 20 이 되어 홈보다 2px 내려간다.

11 을 그대로 둔다. 요소 상단(11 vs 18)이나 콘텐츠 상단(16 vs 18)만 보면 어긋난 것처럼
보이는데, 눈이 보는 것은 글자 상자다. line-height 가 먹는 몫을 빼고 재면 이렇게 틀린다.
