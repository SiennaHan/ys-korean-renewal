0단계 · 활동 목업 읽기

확정 목업 넷을 소스에서 읽었다 — 활동 20화면 · 내비 3화면 · VocaShot 전 흐름 · 게임 17화면.

읽는 방법을 바꿨다

브라우저로 화면을 하나씩 눌러 재는 방식은 패널이 숨겨지면 타이머가 눌려 20화면에 20분이 걸린다. 소스의 빌더 함수와 CSS 규칙을 직접 파싱했다 — 337규칙 · 셀렉터 330개.

칸 상태가 3개다 — 정오답 구분이 없다

build_spec_uiux §3 은 칸을 4상태로 색 구분한다고 적었다 — 정답 fill-correct · 오답 fill-wrong · 채점없음 fill-primary · 미응답 fill-track. §13 은 그 대가(적록색각이상에서 진행바만으로 구별 불가)까지 논한다.

그런데 목업은 done · now · 빈 것 셋뿐이다. 맞았는지 틀렸는지를 진행바에 넣지 않았다. 그러면 §13 의 논의 자체가 성립하지 않는다.

칸 높이도 다르다 — 문서 6 / 목업 5. 현재 위치는 문서가 "높이 10"이라 했는데 목업은 now 에 색으로 표시한다(높이가 같다).

목업대로 간다 — 정오답을 진행바에 넣지 않는다. 기획 판단이다: 표시하면 촌스럽다. §9 참조.

9확정된 결정

진행바에 정오답을 표시하지 않는다

기획 판단 — "정오답 표시하니까 촌스럽다". 목업이 이미 그렇게 되어 있으므로 목업이 그대로 정본이다.

따라오는 것 — build_spec_uiux 두 군데를 고쳐야 한다.

  • §3 칸 상태표 — 4상태를 3상태로. fill-correct·fill-wrong 행을 없앤다
  • §13 접근성 — "진행바가 색으로만 남아 적록색각이상에서 구별 불가, 결과 화면이 담보한다"는 논의가 성립하지 않는다. 진행바에 정오답이 애초에 없으니 담보할 것도 없다. 정오답은 피드백 pill 문구가 전달하고, 그것이 보조가 아니라 유일한 경로가 된다

§14 검증 #10 도 같이 손봐야 한다 — "진행바는 색만이며 그것이 유일한 정보원이 아니다"가 진행 표시만 한다로 바뀐다.

게임은 팔레트가 따로다

VocaShot·게임 화면은 #10b981 · #1e293b · #020617 처럼 토큰 밖 어두운 색을 리터럴로 쓴다. 무대가 검정이라 의도된 것이다.

즉 게임 이관은 토큰으로 치환하는 작업이 아니다 — 그 팔레트를 그대로 가져온다. 활동 셸(밝은 파랑·흰색)과 게임(검정)은 다른 시각 언어이고, 그래야 맞는다.

1단계 방식

목업 CSS 를 클래스 이름째로 앱 스타일시트로 옮긴다. 색만 토큰 semantic 으로 치환한다. Tailwind 유틸리티로 수치를 다시 적지 않는다 — 그게 이번 실패의 원인이었다.

스토리는 목업 화면과 1:1. 목업에 없는 상태를 새로 만들지 않는다 — player.cancel 같은 일이 다시 생기지 않게.
