되돌린 이유를 먼저 적는다

activity_mockups_uiux.html 이 시각 정본이고 handoff_v1.html §03 이 "구현이 목업과 다르면 목업이 기준"이라고 적어 뒀는데, 나는 그 파일을 한 번도 열지 않고 build_spec_uiux.html 의 숫자만으로 컴포넌트를 지었다.

둘이 어긋난다. 목업의 선택지는 줄바꿈 칩 73×40 · radius 8 · 15px 인데 내가 만든 것은 전폭 카드 · min-height 68 · radius 14 · 22px 였다. 다섯 컴포넌트와 스토리 27개를 전부 되돌렸다(01ea83c).

5계획

0단계 — 읽기 코드 쓰기 전

  1. 활동 20화면을 화면별로 DOM 구조·실측 수치로 정리한다. 소스 빌더 함수를 읽는다(브라우저 순회는 느리다).
  2. 나머지 목업 다섯(nav · shell · vocashot 둘 · game)도 같은 방식으로 훑는다.
  3. 정리 결과를 먼저 보여 드린다 — 구조를 제대로 이해했는지 확인받고 나서 코드를 쓴다.
  4. §3 의 어긋남 목록을 확정한다. 특히 진행바 정오답 표시 여부.

1단계 — 목업 CSS 를 앱으로

Tailwind 유틸리티로 숫자를 다시 옮겨 적는 방식이 이번 실패의 원인이었다. 목업이 이미 클래스와 CSS 로 디자인을 들고 있으니 그것을 정본으로 가져온다.

  • 목업의 CSS 를 앱 스타일시트로 이관 — 색은 tokens.css 의 semantic 으로 치환
  • 클래스 이름을 목업과 같게 쓴다. 그래야 대조가 눈으로 된다
  • Storybook 스토리 = 목업 화면과 1:1. 다른 상태를 새로 상상하지 않는다

3단계 — 게임

게임은 기획·콘텐츠가 닫혔고 디자인 이식만 남았다. 활동 셸과 독립이라 병행할 수 있다.

  • 봄소풍 · 서울 퍼즐 — 클래스 주입 0건이라 CSS 만 옮기면 된다
  • 카드 마스터 — 클래스 36개를 JSX 에 심는다
  • 조사 스나이퍼 — 과녁으로 새로(ps-range · ps-reticle · ps-impact-*). 낙하는 없어졌다
  • VocaShot — 개인 플레이 화면과 기계를 같이

막혀 있는 것

  • koreanapi 를 저장소로 들일지 — 1·2번이 서버라 이게 결정돼야 5·8번이 완결된다
  • 진행바 정오답 표시 — 문서와 목업이 어긋난다(§3)
  • 프로덕션 빌드가 깨져 있다 — React 18/19 use import 불일치. 내 변경 전부터 있던 것이고 아직 아무도 안 고쳤다
일하는 방식을 바꾼다

화면을 만드는 작업은 목업을 먼저 열고 시작한다. 숫자 명세는 근거를 찾을 때만 본다 — 정본이 아니기 때문이다. 어긋나면 목업을 따르고 문서 쪽을 고친다.
