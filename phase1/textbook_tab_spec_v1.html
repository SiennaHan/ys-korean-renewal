교재학습 탭 — 활동으로 들어가는 유일한 길

덮개 지도에서 명세와 API 가 비어 있던 자리다 (masterplan_v3 §2). 그런데 화면은 이미 다 만들어져 있다 — 없던 것은 코드가 아니라 적어 둔 규칙이었다. 그래서 이 문서는 새로 설계하지 않고 구현을 읽어 규칙으로 고정한 뒤, 어긋난 곳과 정해야 할 것을 가려낸다. 숫자는 app/src/ 와 목업을 실제로 센 것이다.

01이 화면이 무엇인가

탭 바 다섯 중 둘째다. 기초 활동 5종과 심화 2종으로 들어가는 유일한 입구이고, 자모는 여기서 별도 탭으로 갈라진다. 홈의 "학습 시작하기" 도 결국 이 화면으로 보낸다.

시각 정본은 목업이다

screens_SOT(홈·목록 절) 와 캡처 app/src/screens_ref/nav__book__resume.html. 구현이 목업과 다르면 목업이 기준이다. 다만 목업 대조 스크립트가 이 화면을 검사하지 않는다 — parity:activity 는 activity__* 22개만 본다. 그래서 §07 의 어긋남이 사람 눈에서 빠져나갔다.

03활동 한 줄의 상태 — 다섯

오른쪽 자리는 하나이고 상태에 따라 갈아 낀다. 완료·미완료 둘로 접지 않는다 — 손댔지만 안 끝난 것을 미완료로 묶으면 어디까지 왔는지가 사라진다.

상태보이는 것판정지금
done완료 배지 학습한 문항 수 ≥ 그 과의 총 문항 수돈다
review완료 배지 + 복습 N 다 했지만 다시 볼 것이 남았다 산출되지 않는다 — 화면은 있고 값을 주는 쪽이 없다. §07
doing진행 중 학습한 문항 수 > 0 이고 총 문항 수 미만돈다
none비운다 손대지 않았다. "미완료" 라 부르지 않는다돈다
off흐리게 · 누를 수 없다 지금은 콘텐츠가 없다는 뜻(learn-data-check). 앞으로 권한 잠금도 이 자리를 쓴다 — §06돈다

06API — 있는 것과 필요한 것

무엇상태쓰임

GET /flashcard/word/{id} · GET /chat/list 있다 심화 2종의 완료 판정. 기초와 판정 방식이 다르다 — 문항 수가 아니라 전량 응답·대화 종료로 본다

progress · 플래시카드 낱말 · 대화 목록. 과 칩을 넘길 때마다 다시 나가고, 대화 목록은 급 단위라 같은 급 안에서 과만 바꿔도 통째로 다시 받는다. 과 칩은 손가락으로 훑는 자리라 15과를 넘기면 요청이 45개다.

고칠 방법 둘 — ① 급 단위로 한 번 받아 앱에서 과별로 가른다(응답에 과가 들어 있어야 한다). ② 급·과별로 캐시하고 되돌아올 때 다시 받지 않는다. ①이 낫다. 어차피 /entitlement 도 급 단위로 오므로 모양이 맞는다. dev_spec_v1 §16 에 물음으로 올려야 한다.

07어긋난 것 — 목업이 기준이다

1 · 2 · 3 은 고쳤다 (2026-08-21)

급 라벨과 문구 아홉을 i18n 으로 옮겼고 이미 있던 키 둘을 쓰게 했다. 고치다 보니 같은 버그가 두 곳이었다 — 자모 목록(course-list/jamo.tsx)이 급 탭을 따로 만들고 있어서 거기는 "1권" 이 그대로 남아 있었다. 두 화면이 쓰는 라벨을 textbook/labels.ts 한 곳으로 모아 다시 갈라지지 않게 했다.

2026-08-27 에 게임 다섯도 여기로 들어왔다. 게임은 급·과를 한국어 문자열째로 쥐고 있었다 — 어휘 카드는 vocab["2급"]["4과"] 로 원장을 찾고, 진도는 stage_id="2급_4과" 로 쌓이고, 조사 스나이퍼는 서버가 id="1급" 을 낸다. 즉 그 한국어는 라벨이 아니라 식별자라 못 바꾼다. 그래서 값은 그대로 두고 보여 줄 때만 옮기는 gameLevelLabel · gameLessonLabel 을 같은 파일에 뒀다 — 안에서 이 화면과 같은 catalog.bookTab · catalog.chapterChip 을 쓴다. 급 라벨이 또 갈라지지 않게 하려면 새 화면도 여기를 부르면 된다.

그리고 §10 의 2번을 해서 이 화면이 목업 대조에 들어갔다(23화면). 같은 어긋남이 다시 나면 pnpm parity:activity 가 잡는다 — 실제로 급을 권으로 되돌려 보니 -'1급' +'1권' 으로 잡혔다.

  1. 앱은 "1권", 목업은 "1급" 고쳐야 한다
    탭 라벨을 book.title 에서 그대로 가져오는데 그 값이 "1권"…"8권" 이다. 목업은 "1급" 이고 앱의 다른 곳도 급으로 부른다(i18n 의 "{{level}}급 {{lesson}}과"). 데이터가 아니라 표시를 고친다 — book_id 는 DB 값이라 그대로 두고 라벨만 i18n 으로 만든다. 목업 대조가 이 화면을 안 봐서 빠져나갔다.
  2. 문구 아홉이 한국어로 박혀 있다 5개 언어 앱이다
    기초학습 · 심화학습 그리고 활동 이름 일곱(단어 학습하기 · AI 롤플레잉 · 듣고 질문에 답하기 · 빈칸 채우기 · 읽고 질문에 답하기 · AI 미션 대화 · 단어 플래시카드). 베트남어로 보든 영어로 보든 이 줄만 한국어로 남는다. 이 화면이 활동의 유일한 입구이므로 첫 화면부터 어긋난다.
  3. 이미 있는 i18n 키를 안 쓴다
    catalog.jamoTab("한글")과 catalog.chapterChip("{{seq}}과")이 5개 언어로 다 들어 있는데 코드가 "한글" 과 `${ch.seq}과` 를 직접 쓴다. 번역이 이미 있으니 이 둘은 한 줄씩 바꾸면 끝난다.
  4. 복습 N 이 죽은 화면이다
    review 상태가 타입·렌더·목업·CSS 에 다 있는데 값을 주는 쪽이 없다. 판정 함수는 done·doing·none 만 낸다. ko_review_queue 와 GET /review-queue 가 생기면 살아난다 — 화면 작업이 아니라 서버 작업이다. BLOCKERS §6
  5. 심화 2종만 구 경로다 2026-08-21 이관 완료
    기초 5종은 /learn/* 로 옮겼는데 플래시카드·미션 대화는 /book/chapter/unit/…/$id 에 남아 콘텐츠 ID 를 URL 에 노출한다. 명세가 없애라고 한 바로 그것이다. 이 화면이 실제로 여는 길이므로 이관 우선순위가 높다 — masterplan_v3 §18 의 1번
  6. 2~8급에는 플래시카드가 늘 잠겨 있다 해소 2026-08-25
    급별 콘텐츠를 만드는 쪽으로 정해졌다. 2~8급 플래시카드를 원장에 저작해 배선했고 이제 두 줄이 다 켜진다. "1급 전용 활동으로 명시" 안은 버렸다 — access_and_pricing_v1 §07 의 5번도 같이 해소됐다.
    그래도 남는 것 — 콘텐츠가 없어 꺼진 줄과 고장으로 꺼진 줄을 화면에서 구분할 수 없다는 문제는 그대로다. 플래시카드에서만 안 보이게 됐을 뿐이다

08권한 잠금 — 셋 중 둘이 들어왔다

access_and_pricing_v1 은 "숨기지 않고 보이되 잠근다" 로 정했다. 2026-08-26 에 과 칩과 결제 안내가 들어왔다(037c07a). 아래 표는 그때 무엇이 채워지고 무엇이 남았는지다.

정한 것지금
잠긴 이유를 갈라야 한다 — 콘텐츠 없음과 권한 없음은 사용자에게 다른 뜻이다. 앞은 기다릴 것이 없고 뒤는 결제하면 열린다 됐다. off 는 콘텐츠 없음 그대로고, 권한 없음은 칩의 .locked 와 자물쇠다. 둘이 다르게 보인다
유료 급·과에 자물쇠. 맛보기 과가 어느 것인지가 여기서 보여야 한다 — 1급 4과 · 2급 1과 · 3급 1과 셋뿐이고 한글은 1급 1과다 (2026-08-26 확정. 전에는 "각 급 1과" 로 8과였다 — access_and_pricing_v1 §02) 과 칩은 됐다. 잠긴 칩에 자물쇠가 붙고, 무료 과가 자동으로 골라진다.
급 탭은 아직이다 — 4~8급은 무료 과가 하나도 없는데 탭만 보면 알 수 없다. 탭에 자물쇠를 붙이려면 목업(nav__book__resume)도 같이 나가야 한다
권한 잠금은 누르면 결제 화면으로 보낸다. 게스트면 로그인 먼저. 기관 학생이면 "학교에 문의" 로 — 결제 화면을 띄우면 안 된다 됐다. paywall-panel.tsx 가 게스트·개인·만료·기관 넷으로 갈린다. 기관 학생에게는 가격도 결제 버튼도 안 보인다.
결제 화면 자체는 아직 없다 — 버튼이 눌리지 않는 채로 있다(§09 의 그 뒤)

권한 판정을 이 화면에서 계산하지 않는다. GET /entitlement 의 응답만 믿는다 — 출처(무료·학교 계약·개인 결제)가 늘어도 이 화면은 고치지 않는다.

무료 목록을 페이월 문구에 적지 마라. 처음에는 다섯 언어에 "1급 4과 · 2급 1과 · 3급 1과" 라고 적어 뒀는데, 그러면 경계가 두 곳에 있게 되고 free_scope.py 머리말이 못 박은 대로 갈라진다. 실제로 잠긴 1급 4과 위에서 그 목록이 "1급 4과는 지금 볼 수 있습니다"라고 말하고 있었다. 2026-08-27 페이월 v1.1은 이 긴 목록을 화면에서 없앴다. 어느 과에 자물쇠를 붙일지는 여전히 서버 응답만 믿는다.

09정해야 할 것

  1. 활동 이름을 무엇으로 부르나 문구
    한국어로 박힌 일곱을 5개 언어로 옮기려면 원문을 먼저 확정해야 한다. 지금 이름이 목업과 같으므로 그대로 쓰는 것을 권한다 — 다만 "빈칸 채우기" 는 라우트가 /learn/grammar 이고 menu_type 은 fill-blank 라 셋이 다 다르다. 사용자에게 보이는 이름만 정하면 되고 나머지는 건드리지 않는다.
  2. 한 과를 열 때 요청 셋을 하나로 줄일지 API
    §06 의 권고는 급 단위로 한 번이다. 응답에 과가 들어가야 하므로 /learning-record/progress 의 모양이 바뀐다 — dev_spec_v1 §16 에 올려 개발자와 정할 물음이다.
  3. 2~8급 플래시카드를 만들지, 1급 전용으로 명시할지 해소 2026-08-25
    §07 의 6번. 만드는 쪽으로 정해졌다 — 원장에 2~8급을 저작해 배선했고 이제 급마다 값이 나란하다. 화면에서 "1급에만 있어요" 를 말할 일은 없어졌다.
  4. 목업 대조에 이 화면을 넣을지 도구
    권/급 어긋남이 목업 대조가 이 화면을 안 봐서 빠져나갔다. 캡처(nav__book__resume.html)는 이미 있으므로 parity:activity 에 nav 화면 다섯을 더하는 것은 작은 일이다. 권한다 — 같은 실수가 홈·자모 목록에서도 날 수 있다.
