0문서 규칙과 용어

  • 이 문서가 단일 진실 원본(SoT)이다. 화면·정책·지표의 근거는 항상 이 문서이며, 코드와 다르면 어느 쪽이 틀렸는지 이 문서 기준으로 판정한다.
  • 2층 구조: 1부(0~4장)는 시스템 문서 — 화면이 늘어나도 바뀌지 않는 원칙. 2부(5~8장)는 화면·기능 명세 — 원칙을 인용해서만 쓴다.
  • 출시 후 변경은 반드시 11장 체인지로그에 기록 후 개발 요청한다. 구두·메신저 단발 요청 금지. 고객사 요구도 동일 경로를 거친다(11장 프로세스).
  • 용어: 급(1~8, 구 "권"에서 개칭 — D1-b) → 과(급당 12~15) → 활동(과당 7±) → 문항. 세션 = 활동 1회 수행. 복습 큐 = 오답·몰라요가 예약되는 대기열. 급은 화면 노출 라벨, 스키마 컬럼명 book_id는 유지(D1-b). 사용자 노출 문구는 "문제"가 아니라 "활동"을 쓴다.

1선결 결정 D1~D7

아래 7개가 확정되어야 2장 이후가 흔들리지 않는다. 각 항목의 권고안은 역기획 근거와 함께 제시하며, 확정 시 이 절의 "권고"를 "확정"으로 바꾸고 체인지로그에 기록한다.

D1

포지셔닝 · 계정 모델 v0.2 개정

확정된 방향(사용자 지시, 2026-08-13): B2B(어학당 수강생, 현행 학교 발급)와 B2C(어학당 미수강 개인 학습자, 교재 QR 진입)를 함께 지원하는 하이브리드 모델. B2C는 진입 시 일부 기능만 무료 공개하고 나머지는 결제 후 공개(프리미엄 — 경계는 D7).

세그먼트진입 경로계정과금
B2B 학습자어학당이 어드민에서 엑셀 대량 발급학교 소속(school_code)학교 계약(현행 방식 유지 — 개인 결제 없음)
B2C 학습자 (신규)교재(『연세 글로벌 한국어』) 실물의 QR코드 → 앱 진입자가 가입(개인, 학교 미소속)프리미엄 — 무료 구간 + 결제 후 잠금 해제
게스트비로그인 체험(현행)임시(guest-uuid)B2C 무료 구간과 동일 취급 — 로그인 시 B2C 계정으로 전환
권고학교 온보딩(승인 워크플로)은 그대로 두고, B2C 전용 자가 가입을 신설한다(현행 앱엔 개인 자가 가입 화면 자체가 없음 — 신규 구축). 비밀번호 재설정 완성(디자인 5개 언어 완료, 프론트 TODO 상태)은 두 세그먼트 공통으로 이번에 함께 처리한다. B2C 계정에는 school_code = null + tier: free|premium을 부여해 기존 ko_user role 체계(3.1 라우팅 원칙과 별개)를 최대한 재사용한다.
영향: 2장 페르소나·정의 전면 개정 · 3장 접근 제어(신설, D7) · 6장 온보딩·결제 화면 신설 · 7장 어드민에 B2C/결제 관리 추가 · 9장 PG 연동 · 콘텐츠(D3)는 교재 자체가 바뀌므로 별도 이슈.
D1-b

교재 소스 전환 v0.2 신설

확정된 방향(사용자 지시): 콘텐츠 원천을 『3주 완성 연세 한국어』에서 『연세 글로벌 한국어』(1~8급, 최종본 26.8.10)로 완전히 교체한다. 구 교재는 폐기.

구조는 그대로다 — 다행인 부분

로컬 마스터 시트(연세글로벌한국어_어휘마스터.xlsx) 실측 확인: 급수·과 체계가 구 교재와 동일하다 — 1급=4~15과(1~3과는 한글), 2~8급=1~15과. 즉 앱의 권/급 내비게이션·상태 모델·라우트 구조(3장)는 재설계가 필요 없고, 콘텐츠만 새 교재 기준으로 재구축하면 된다. 어휘·문법 마스터는 이미 YGK-{급}-{과}-{순번} / YGKG-{급}-{과}-{순번} ID 체계로 착수돼 있다(어휘 2,942항목·문법 234항목, 국립국어원 표준등급 매칭 포함) — 4장 콘텐츠 파이프라인의 실제 출발점으로 채택한다.

가벼워지지 않는 부분 — 재저작이 필요한 파생 콘텐츠

구 앱의 학습활동(단어퀴즈 1,149문항·롤플레이 995턴·듣기 679문항·빈칸 836문항·읽기 지문 117개·미션대화 117개)은 전부 구 교재 본문 기반이라 재사용 불가하다. 마스터 시트는 표제어·문법 항목까지만 있고, 대화문·듣기 스크립트·읽기 지문·활동 문항은 새 교재에서 다시 저작해야 한다. 이 재저작 규모가 리뉴얼 일정의 최대 변수 — 4.2절에서 콘텐츠팀 작업량으로 별도 산정한다.

용어 정리 권고새 교재의 공식 단위는 "급"이다. 구 앱 UI의 "1권~8권" 표기를 "1급~8급"으로 교체(학습자가 실물 교재를 펼쳤을 때 앱과 표기가 일치해야 함). 내부 스키마의 book_id는 유지하되 화면 라벨만 교체.
영향: 4장 전면 개정 · 6장 화면 라벨(권→급) · 10장 마이그레이션(콘텐츠는 이관이 아니라 재저작이므로 일정 재산정 필요).
D2

학습 단위 · 상태 모델

질문: 진도·완료·복습을 무엇으로 정의하는가. 현행은 완료/미완료 이진 + 활동별 제각각 기록(자모 무기록, 빈칸 정답만 저장)이다.

권고 (코어 루프 목업 v1 채택) 활동 상태 4단계: 미학습 → 진행 중 → 완료 → 복습 권장.
  • 오답은 "기록"이 아니라 "예약" — 오답·몰라요는 복습 큐에 들어가고, 소화해야 상태가 완료로 정리된다. 플래시카드 repeat 패턴을 전 활동으로 일반화.
  • 이어하기 = 문항 단위. ✕(종료)는 항상 현재 위치를 저장한다 — "저장 없이 나가기" 상태를 없앤다.
  • 스트릭 = "오늘 할 일 1개 완료" 기준(단순 접속 아님). 오늘 할 일 = 이어하기 or 복습 큐 최상단.
  • 전 활동 공통 기록: 자모·게임 포함 최소 완료 이벤트 저장. 빈칸 채우기의 정답만 저장 버그는 리뉴얼 전 수정(10장 Phase 0).
영향: 3장 상태 머신 · 5장 홈/플레이어 셸 · 데이터(learning_record 확장 + 복습 큐 테이블 신설). 지표 정의는 2.3절.
D3

콘텐츠 단일 원본(SoT)

질문: 콘텐츠 원본은 어디인가. 현행은 3중 소스(프론트 번들 16MB / 백엔드 seed JSON / DB) + ID 4계열(YK·C·F·book-chapter) + 분모 하드코딩(생성 스크립트 유실).

옵션내용평가
A. 현행 유지프론트 번들배포=콘텐츠 수정. 16MB 번들. 어드민 편집 불가
B. 전량 DBDB + API + 어드민 편집게임 콘텐츠에서 이미 검증된 패턴. 오프라인 불가
C. 정적 패키지버전닝된 콘텐츠 번들 + CDN성능 유리하나 편집 파이프라인 별도 필요
권고B — DB로 이관. 게임 콘텐츠 DB화 + 어드민 에디터가 이미 검증한 길이다. ① 콘텐츠 ID 단일 체계 신설: 어휘·문법 마스터의 YGK-{급}-{과}-{순번} 스킴을 활동·문항까지 확장(4.1). 구 ID 4계열(YK·C·F·book-chapter)은 매핑 없이 완전 폐기 — 학습 기록을 승계하지 않기로 확정(10장)했으므로 매핑 테이블이 불필요 ② 파이프라인 공식화: 교재 PDF → 7탭 콘텐츠 엑셀 → ingest 스크립트(유실분 재작성) → DB. 검수 상태 컬럼 포함 ③ 어드민 편집 범위: 오탈자·번역·오답 교체·음성 재생성 트리거 ④ 표현클립: 자막 인덱스를 서버 검색 API로 (번들 11.7MB 제거) ⑤ 프론트 초기 번들 예산 < 1MB (9장).
영향: 4장 전체 · 7장 어드민 · 9장 성능 · 10장 마이그레이션이 가장 큰 공사. C로 바뀌면 4장 파이프라인만 교체되고 ID 체계는 동일.
D4

다국어 원칙

질문: 어디까지 번역하는가. 현행은 i18n 인프라(5개 언어)가 있으나 적용이 인증·MY·게임뿐이고, 학습 화면은 한국어 하드코딩.

권고3원칙으로 고정한다.
  • 원칙 1 — 학습 대상 한국어는 절대 번역하지 않는다 (문항 텍스트, 선택지, 대화문).
  • 원칙 2 — 지시문은 한국어 + UI 언어 병기 (코어 루프 목업 규칙). 예: "빈칸에 알맞은 것을 고르세요." + "Choose the correct word."
  • 원칙 3 — UI·피드백·결과는 100% UI 언어를 따른다 (LLM 피드백은 이미 UI 언어 생성 — 이 패턴을 표준으로).
지원 언어 5종(en/ko/ja/zh/vi)·기본 en 유지, 최초 실행 시 언어 선택 노출. 콘텐츠 번역 컬럼의 구멍(단어 학습 vi 누락)은 콘텐츠 이관(D3) 때 필수 컬럼으로 강제.
영향: 3장 적용 범위 표 · 전 화면 명세 · 4장 콘텐츠 스키마(번역 필수 컬럼).
D5

디자인 시스템과 게임의 위치

질문: 시스템의 원본은 무엇이고, 게임(현행 5종 각자 룩)을 어디까지 통일하는가.

권고Figma 스타일 가이드(Pretendard 타입 스케일 · Primary #0180FF · 컴포넌트 8종)를 디자인 SoT로 승격하고 코드 토큰으로 1:1 대응시킨다. 플레이어 공통 셸이 리뉴얼의 핵심(5장): 헤더·진행 세그먼트바·피드백·결과 화면을 전 활동이 공유하고 콘텐츠만 갈아끼운다. 게임은 "같은 시스템 안의 놀이 모드" — 셸·타이포·진입/결과 화면은 시스템을 따르고, 플레이 내부 표현만 자유(다크 게임 룩은 다크 토큰 변형으로 흡수). 전환 모션 규칙 포함(9장 성능 예산과 연동).
영향: 5·6장 전체 · Figma 파일 재편(기획서-디자인 섹션 대응 규칙).
D6

음성 · AI 전략

질문: STT 3사 섀도우 수집(현재 100% 수집=비용 3배)을 언제 끝내고 무엇을 고르나. 발음평가(계산 후 버림)를 정식 채택하나.

권고
  • STT: 종료 조건을 수치로 정의 — 예: 급수×활동별 표본 n건 도달 시 샘플링 10%로 하향, 분기 리뷰로 엔진 결정(판단 기준: 내용 불일치율·지연·단가). 결정 전까지 OpenAI 주전사 유지.
  • 발음평가: 정식 채택하되 전제 2개 — ① 결과 저장 스키마 신설(현행은 계산 후 폐기) + 리포트 노출(미션대화 리포트의 발음 축을 실측치로 교체) ② Tutorus 프로덕션 계약·전용 자격증명 전환(현행 dev+타사 계정은 차단 리스크).
  • TTS: 캐시 코어·사전생성 배치 유지. 단어 캐시 키(레거시 naver) 정리는 D3 콘텐츠 이관과 동일 마이그레이션에서 1회 처리.
  • LLM: 무인증 /speech/*·/report 인증 필수 + rate limit 복구를 리뉴얼 이전 핫픽스로(10장 Phase 0). 프롬프트는 전부 DB/설정으로 — 코드 하드코딩 금지.
영향: 8장 전체 · 7장 STT비교 도구 존치 여부 · 운영비.
D7

프리미엄 경계와 인타이틀먼트 모델 v0.2 신설

확정 — 이 절은 대체됐다 (2026-08-20) 정본은 phase1/access_and_pricing_v1.html 이다. 아래 D7 은 8월 13일의 제안이고 확정된 내용과 세 곳이 다르다 — ① 무료 범위가 훨씬 좁아졌다. 여기서는 "한글 + 1급 전체 + 게임 전체 + 클립" 을 제안했지만 확정은 각 급 한 과 · 자모 첫 과 · 게임은 VocaShot·봄소풍만(클립은 그대로 전부 무료)이다. ② QR 은 결제와 무관해졌다. 책값과 앱 사용료를 별도로 하기로 했으므로 라이선스 키(옵션 B)도, 프로모션 코드도 쓰지 않는다. QR 은 지금처럼 유입 추적으로 남는다. ③ 결제는 PG 직접 연동이다. 이 앱은 웹앱이라 스토어가 개입하지 않는다.

질문: B2C 진입자에게 뭘 무료로 열어주고 뭘 결제로 잠그는가. QR이 실물 책 한 권과 연결되는 라이선스 키인가, 아니면 단순 유입 채널이고 결제는 별개 구독인가.

7-a. 인타이틀먼트 구조

옵션내용평가
A. QR = 순수 유입 채널QR은 회원가입 랜딩으로만 기능. 결제는 앱 내 구독으로 완전히 독립구현 단순, 표준 프리미엄 앱 패턴(듀오링고류). 책 1권=앱 n대 사용 같은 통제 불가
B. QR = 1회성 라이선스 키QR마다 고유 코드 발급 → 1회 redeem으로 특정 혜택(예: 1개월 프리미엄) 부여, 이후 구독은 별도"책 사면 앱도 딸려온다"는 마케팅 메시지 명확. 코드 발급·인쇄·재고 관리 필요(출판 프로세스에 의존)
권고A를 기본, B를 1단계 확장으로. 최초 출시는 QR을 순수 유입 채널로 단순하게 만들고(현행 /qr 익명 추적 인프라를 계정 가입 랜딩으로 확장 재사용), 실물 QR 안쪽에 일회성 프로모션 코드(예: "첫 달 무료")를 옵션으로 얹는 방식(B의 가벼운 버전)으로 시작한다. 완전한 1:1 라이선스 키 관리(B)는 출판 인쇄 프로세스와 맞물려 있어 리뉴얼 1차 범위 밖 — 필요성이 확인되면 Phase 3 이후 별도 과제로.

3.6 접근 제어 — B2C 프리미엄 게이팅 (D7 신설)

  • 서버가 최종 판정 — 클라이언트 잠금 해제는 UX일 뿐, API 레벨에서 재검증(3.5 보안 원칙과 동일 기조).

"이관"이 아니라 "재저작"이다

5.1 홈

  • 오늘 할 일 카드(최상단): 이어하기(문항 단위 위치 표기 — "10과 듣기 · 3/6 문항") 1개 + 복습 대기 카드(신규 — "복습할 문항 12개"). 스트릭은 이 카드 완료와 연동.
  • 지표 재정의: 현재 과 진행 = 완료 활동 수/과 활동 수(문항 아님), 오늘 학습 시간, 주간 차트. 산식은 2.3 표를 인용.

5.2 교재학습

  • 급 커버에 진행률 링, 과 칩에 상태 점(미학습·진행·완료·복습), 과 카드에 완료 수 + 예상 남은 시간, 활동 행에 분량("문항 6개 · 약 3분")과 정지 지점. B2C 잠긴 급은 자물쇠 뱃지(3.6).

7관리자 콘솔

  • 학습 리포트 신설 — B2B 최대 공백. 학교→반→학생 드릴다운: 활성률·과 진행·복습 소화·말하기 통과율(2.3 지표 재사용). 교수자(student_admin)는 자기 반만.
  • 콘텐츠 편집을 교재 콘텐츠까지 확장(4.1). 게임 에디터 패턴 재사용.
  • 권한을 서버에서 강제(3.5), 개발 도구(STT비교·TTS비교)는 도구 섹션으로 분리하고 D6 결정 후 존치 재검토.
  • VocaShot: 참가 QR을 학생 앱 도메인으로 수정, 문제 세트를 localStorage → 서버 저장.
  • B2C·결제 관리 (신설, D7): 마스터 전용 — 구독 현황(무료/유료 전환율), 매출·환불 처리, 프로모션 코드 발급(7-a 옵션 B의 가벼운 버전). QR 스캔 통계(현행 ko_qr_scan)에 "가입 전환율" 지표 추가 — 기존 익명 마케팅 추적을 B2C 퍼널 추적으로 확장.

8AI·음성 (D6 구체화)

  • 발화 평가 결과 저장 스키마: utterance_eval(user, activity, 문항, pass, 발음 5축, 약점 단어/음소, engine, ts) — 리포트·복습 큐가 소비.
  • 프롬프트 관리: 미션대화 패턴(DB 저장)을 전 LLM 유스케이스로 확장, 변경은 체인지로그 대상.
  • TTS: 캐시 코어 유지. 콘텐츠 이관 시 단어 캐시 키 재계산 1회. 신규 콘텐츠는 ingest가 사전생성 배치 자동 큐잉.

9비기능 요구

  • 번들 예산: 초기 JS < 1MB, 라우트 코드 스플리팅. 콘텐츠는 API/캐시(D3).
  • 성능: 화면 전환 300ms 이내 응답(현행 긴 fade 제거), 오디오 첫 재생 1s 이내(사전생성 유지).
  • 관측성: "조용한 실패 금지" — dashboard류 집계 실패는 에러로 표면화 + 알림. 분석 이벤트 최소 셋(활동 시작/완료/오답/복습 소화/스트릭)을 지표(2.3)와 1:1로.
  • 운영: DB 마이그레이션 도구(Alembic) 도입, 배포 순서 문서 유지(게임 콘텐츠 패턴), stop.sh 등 운영 스크립트 정비.
  • 결제 (신설, D7): 국내 PG 연동(정기결제 지원 필수 — 구독형), 카드 정보 비저장(PG 위탁), 환불·해지 API, 매출 정산 배치. 벤더 선정은 별도 검토(토스페이먼츠/이니시스 등).

10마이그레이션과 출시 단계 v0.2 전면 재편

교재 교체로 콘텐츠는 "이관"이 아니라 "재저작"이 됐다(4.2). 그래서 단계 순서를 셸·시스템이 먼저, 무거운 콘텐츠(대화 기반 활동)는 나중으로 재배치하고, 어휘·문법이 이미 준비된 활동(단어·플래시카드·문법 클로즈)부터 조기 출시가 가능하도록 짰다. B2C·결제는 별도 트랙(Phase 2.5)으로 분리해 B2B 트랙과 병행 가능하게 한다.

단계내용비고
Phase 0 (선행 핫픽스)보안 기준선(3.5) + fill-blank 수정 + VocaShot QR + 테스트 라우트 제거리뉴얼과 독립, 즉시 요청 가능
Phase 1 (셸)플레이어 공통 셸 + 라우트 통일("권"→"급" 라벨 포함) + 전 활동 기록 통합(상태 4단계) + 접근 제어 게이트(3.6, 콘텐츠 없이도 배선 가능) + 홈 개편콘텐츠는 구 앱 번들을 임시로 유지하며 셸만 먼저 검증
Phase 2 (콘텐츠 SoT + 1차 저작)DB 이관 인프라 + ingest + 어드민 편집 + 어휘·문법 의존 활동(단어학습·플래시카드 전 급·문법 클로즈) 저작·출시이 시점에 구 교재(3주완성) 콘텐츠·구 학습 기록 전면 폐기(아래 확정) — 승계 로직 불필요
Phase 2.5 (B2C·결제) 신규 트랙자가 가입 + QR 랜딩 + 접근 제어 게이트 활성화 + PG 연동 + 어드민 결제 관리Phase 2 완료(잠글 콘텐츠 존재) 후 진행. B2B 트랙과 독립 진행 가능
Phase 3 (무거운 콘텐츠 + 루프 완성)대화문·듣기·읽기·미션대화 저작·출시 + 복습 큐 + 결과 화면 규격 전면 적용 + 발음평가 정식화 + 어드민 학습 리포트지표 대시보드 포함
확정 — 기존 학습 기록은 폐기한다 v0.2 확정

구 교재(3주완성) 기준으로 쌓인 완료·플래시카드·미션대화 기록은 새 콘텐츠의 상태로 승계하지 않고 폐기한다. 새 콘텐츠에 대해서는 전원 미학습부터 시작한다.

근거(확정 사유): 실사용 이력이 유의미하게 쌓이지 않은 단계이므로 승계 가치가 없고, 승계할 경우 "같은 급-과 위치의 다른 내용"을 완료로 표기하는 오류가 발생한다. 따라서 이관 로직·매핑 테이블을 만들 필요가 없다 — 10장 Phase 2의 마이그레이션 부담이 그만큼 줄어든다.

영향: 학습 기록 테이블은 초기화(또는 archived 플래그 후 조회 제외). 구 콘텐츠 ID 매핑 테이블(D3 ①에서 "구 YK·C·F는 매핑 테이블로 보존") 불필요 — 구 ID 체계 완전 폐기. 계정·학교·반 정보는 그대로 유지한다.
