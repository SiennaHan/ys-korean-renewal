# 문서 검수 — $ARGUMENTS

절차의 정본은 `docs/doc_review_v1.md` 다. 아래는 그것을 명령형으로 옮긴 것이고,
둘이 어긋나면 그 문서가 이긴다.

## 이 명령은 고치지 않는다

**찾아서 보고만 한다.** 고치는 것은 사람이 결과를 보고 정한다.
읽기만 한 검수가 **참인 문장을 거짓으로 "고치는"** 것이 가장 나쁜 결과라서
아예 권한을 안 준다(`allowed-tools` 에 편집 도구가 없다).

## 무엇을 읽나

`$ARGUMENTS` 가 있으면 그것만 읽는다. 없으면 **문 넷 + 인계서**를 읽는다 —
`CLAUDE.md` · `README.md` · `BLOCKERS.md` **§0 만** · `docs/INDEX.md` ·
`docs/developer_tasks.md`.

**읽지 않는 것** — `screens_SOT.html` · `shell_spec_v1.html` · `games_spec_v1.html`.
셋이 문서 분량의 대부분인데 값과 마크업은 이미 `parity:activity` · `check:css` ·
`design-values-check` 가 지킨다. 사람이 다시 훑을 자리가 아니다.
`BLOCKERS.md` 는 4천 줄이 넘으므로 **통째로 읽지 마라** — §0 이 표 한 장으로 요약한다.

## 반드시 지킬 것 — 도구를 쥐고 읽는다

**주장마다 `ls` · `grep` · `git log` · 실제 실행 중 하나로 확인한다.**
읽기만 하면 그럴듯한 지적을 지어낸다. 실제로 이렇게 갈렸다 —

    「.env.example 이 없다」      → ls 로 재니 있었다
    「1급이 12과인 파일 11개」     → 세니 10개였다
    「복습 N 에 값을 주는 쪽이 없다」→ grep 하니 정말 0곳이라 안 건드렸다
    「레거시 화면」               → git log 로 보니 그 트리는 이미 걷어냈다

**확인하지 못한 것은 「틀렸다」고 적지 마라.** 물음으로 남긴다.

## 의심할 다섯

1. **가리키는 곳** — `문서 §N` 이 정말 그 이야기를 하는 절인가.
   번호가 살아 있어도 내용이 다를 수 있다. **그 절을 열어라.**
   (`CLAUDE.md` 가 `BLOCKERS §3-b` 를 두 곳에서 가리켰는데 그 절은 딴 이야기였다.
   절이 실재하니 참조 검사는 통과한다.)
2. **지킬 수 있는 지시인가** — "여기부터 읽어라" 의 대상이 4천 줄이 됐거나,
   "이 셋을 돌려라" 를 CI 가 대신하게 됐을 수 있다. **크기를 재고 실제로 돌려 봐라.**
3. **「없다 · 아직 · 남았다」** — 끝난 일이 그대로 앉아 있는가.
   **제목과 상태 알약(`pill open`)부터 봐라.** 4천 줄을 훑을 때 사람이 읽는 것은 제목이다.
4. **산문과 표가 갈렸나** — 표만 고치고 그것을 설명하는 문장이 안 따라온 자리.
5. **두 문서가 같은 것을 다르게 말하나** — 특히 **요약한 쪽**이 좁게 적혀 있기 쉽다.

> **「실측으로 확인」 같은 말이 붙은 절을 특히 의심해라.** 재 봤다는 말이 있으면
> 다음 사람이 다시 재지 않는다 — 그래서 가장 오래 낡는다.

## 먼저 돌릴 것

```bash
python3 docs/check_docs.py          # 기계가 잡는 것부터 치운다
python3 docs/gen_status.py --check  # 「지금 상태」가 코드와 같은가
```

`[관찰 기준]` 이 울면 **그 문서가 이번 검수 대상이다.**

## 보고 형식

찾은 것마다 이렇게 적는다. 고치지는 않는다.

    파일:줄   적혀 있는 것  →  실제        확인한 방법
    무엇을 고쳐야 하는지 한 줄
    (확인 못 했으면 그렇게 적고 물음으로 남긴다)

마지막에 **톱니로 넘길 것**을 따로 적는다 — 틀린 숫자는 `specs` 에 세는 함수로,
한 번 거짓이라 밝혀진 문장은 `STALE_PHRASES` 지뢰로. 넣을 때는
`docs/check_docs_probe.py` 에 **대조군도 같이** 넣어야 한다.
