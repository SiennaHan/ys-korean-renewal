04읽는 순서

  1. 활동 UI/UX 목업을 먼저 열어 보세요
    버튼을 눌러 상태를 바꿔 보시면 무엇을 만드는지 5분이면 감이 옵니다. 문서보다 이게 빠릅니다.
  2. 구현 사양 + API 필드 스키마
    이 둘이 구현에 필요한 전부입니다. 화면은 구현 사양, 서버 계약은 API 스키마.
  3. Phase 1 개발 명세
    DB DDL과 라우트 매핑. 위 둘과 겹치는 부분은 구현 사양이 우선입니다.
  4. 셸 컴포넌트 명세 · G2 — 근거가 궁금할 때만
    "왜 이 값인가" "오답이면 왜 정답을 안 알려주나" 같은 판단의 이유가 들어 있습니다. 검토 이력이 섞여 있어 구현 기준으로는 쓰지 마시고, 확정값은 구현 사양을 보세요.
AI에게 시키실 경우

구현 사양 · API 스키마 · 목업 셋만 주시는 편이 낫습니다. 셸 컴포넌트 명세와 G2에는 "앞서 X라고 쓴 것을 정정한다" 같은 검토 이력이 여러 군데 있어서, AI가 정정당한 쪽을 구현할 수 있습니다.
