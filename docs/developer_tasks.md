## 0. 역할 경계

| 담당 | 정하는 것 | 하지 않는 것 |
|---|---|---|
| 기획·제품 책임자 | 가격·환불·보관기간·노출 게이트·정확도 기준·최종 법률 문구, 화면 승인 | DB 구조·웹훅 검증·재시도 정책을 감으로 지정하지 않는다 |
| 개발자 | DB 마이그레이션·API·권한·보안·외부 연동·관측·테스트·배포·롤백 | 미정인 가격·보관기간·정답률을 대신 결정하지 않는다 |
| 디자인 | 시각 정본·상태별 문구·다섯 언어 레이아웃 승인 | 결제 성공·권한 부여를 클라이언트 상태만으로 확정하지 않는다 |

앱 코드를 고쳐야 하는 작업도 있다. 다만 개발자가 앱에서 맡는 범위는 **API 배선·오류 상태·접근성·분석 이벤트**다.

## 3. 개발 작업 카드

상태 표기: **READY**는 바로 시작 가능, **PARTIAL**은 기반 작업까지만 가능,

### DEV-01 · QR을 홈으로 보내기 — READY · P0

**목적:** 책의 QR은 권한 키가 아니라 유입 경로다. 로그인 여부와 무관하게 게스트 세션을
보장한 뒤 홈(`/main`)으로 보낸다.

**현재:** `app/src/routes/qr.tsx`는 `PUBLIC_QR_WEB_REDIRECT_URL`의 기본값 `/`을 쓴다.
비로그인 사용자가 `/`을 거치면 로그인으로 갈 수 있어 확정 정책과 다르다.

**구현 범위**

1. 스캔 기록 요청은 한 번만 보낸다. 실패해도 사용자를 빈 화면에 두지 않는다.
2. 로그인 토큰이 없으면 기존 게스트 인증 흐름으로 게스트 세션을 만든다.
3. 언어 설정과 QR 추적 정보는 보존하고 `/main`으로 이동한다.
4. QR은 무료 범위 이상의 권한을 만들지 않는다.

**완료 판정**

- 새 브라우저·기존 게스트·로그인 계정 세 경우가 모두 홈에 도착한다.
- 새 브라우저는 도착 즉시 `GET /entitlement`와 학습 기록 API를 호출할 수 있다.
- 잘못된 QR 코드·추적 API 실패·중복 탭에서도 무한 리다이렉트나 중복 스캔이 없다.
- 한국어·영어를 포함한 언어 설정이 이동 전후 동일하다.

### DEV-02 · 표현클립 신고를 안전하게 저장하기 — READY · P0

**목적:** 신고가 실제로 저장되고, 신고 한 건이 영상을 전 사용자에게서 즉시 숨기지 않게 한다.

**현재**

- `ko_error_report.target_id`는 `varchar(10)`인데 유튜브 ID는 11자라 `POST /report`가 500이다.
- 신고 영상 제외 로직은 살아 있어 컬럼만 먼저 늘리면 익명 한 명이 영상을 전원에게서 숨길 수 있다.
- `POST /report` 와 `GET /report/list/{category}` 가 **둘 다 무인증**이고(라우트에 `Depends` 가 없다), 클라이언트는 실패를 성공처럼 닫는다.

**반드시 지킬 구현 순서**

1. 앱의 신고 결과를 **제외가 아니라 하위 정렬**로 바꾼다. 재생 불가 코드 100·101·150만 제외한다.
2. 그다음 DB를 마이그레이션한다. 신고 단위는 영상이 아니라 **영상 구간**이며 `target_id`는 최소 32자다.
3. 구간 시작 초·검색어·맞은 대본 줄·신고 사유 코드를 저장한다.
4. 두 신고 API 모두 로그인/게스트 토큰을 받고 토큰 없는 호출은 거부한다.
5. `inappropriate`는 기존 문의 채널로 알리되, 슬랙 실패가 DB 저장을 되돌리지 않게 한다.
6. 앱은 저장 실패 시 실패 상태와 재시도를 보여 준다.

**완료 판정**

- 같은 영상의 서로 다른 구간을 별도로 신고할 수 있다.
- `audio_quality` 신고 후 해당 구간은 사라지지 않고 같은 우선순위 안에서 뒤로 간다.
- `inappropriate` 신고는 DB에 먼저 남고 조치 가능한 시점 링크와 맥락이 알림에 포함된다.
- 토큰 없는 요청은 401/403, 게스트·회원 요청은 정상 처리된다.
- 중복 전송은 중복 행·중복 알림을 만들지 않거나 명시한 멱등 규칙으로 처리된다.
- 마이그레이션 전후 데이터와 롤백 절차가 PR에 포함된다.

상세 근거는 `BLOCKERS.md` §6-e와 `clip_spec_v1.html` §05~§06이다.

### DEV-03 · 비밀번호 재설정과 메일 발송 — PARTIAL · P0

**목적:** 현재의 안내 화면을 실제 단일 사용·만료형 재설정 흐름으로 연결한다.

**현재:** `MAIL_RESET_READY=false`이고 화면만 있다. 서버에 재설정 요청/확정 API와 메일 발송 수단이 없다.

**지금 시작할 수 있는 기반 작업**

1. 메일 사업자 비교안과 발신 도메인 DNS 요구사항을 제출한다.
2. 재설정 토큰 표를 만든다: 사용자, **해시된 토큰**, 만료 시각, 사용 시각, 생성 시각.
3. 요청 API는 존재하지 않는 이메일에도 같은 응답과 유사한 처리 시간을 쓴다.
4. 확정 API는 서버에서 회원가입과 같은 비밀번호 규칙을 검증한다.
5. 토큰은 24시간 이내의 기획 승인값, 단일 사용, 새 요청 시 이전 미사용 토큰 무효화를 기본안으로 제시한다.
6. 다섯 언어 메일은 같은 딥링크 계약을 쓰고 토큰·비밀번호를 로그에 남기지 않는다.
7. 이메일·IP 기준 속도 제한과 감사 로그를 넣는다.

**목적:** 외부 응답이 늦으면 학생이 몇 분을 빈 화면에서 기다리는 지금 상태를 없앤다.

**현재:** `api/xternal/` 여섯 중 **`openai.py`와 `gcloud.py`만 타임아웃이 0곳이다**
(`gemini.py`·`rtzr.py`·`tutorus.py`·`slack.py`에는 있다). 그런데 그 둘을 지나는 것이
**STT·TTS·미션 대화 응답·미션 완료 판정 전부**다. SDK 기본값에 맡겨져 있어 실질적으로 멈춘 것과 같다.
재시도는 `gemini.py` 한 곳에만 있다.

**구현 범위**

1. `openai.py`·`gcloud.py`의 모든 호출에 연결·읽기 타임아웃을 준다. 값은 화면이 기다릴 수 있는 시간에서 거꾸로 정한다.
2. 스트리밍과 비스트리밍을 갈라 잡는다 — 첫 토큰까지의 시간과 전체 시간은 다르다.
3. 재시도는 **멱등한 호출에만** 넣고 횟수·간격을 적는다. 채팅 응답을 말없이 두 번 만들지 않는다.
4. 앱은 타임아웃을 오류가 아니라 **다시 시도할 수 있는 상태**로 그린다. 녹음·입력 내용을 잃지 않는다.

**완료 판정**

- 외부를 일부러 늦춰 놓고 각 활동이 정해진 시간 안에 실패 화면에 도달한다.
- 실패 뒤 재시도가 되고, 재시도로 중복 기록·중복 과금이 생기지 않는다.
- 타임아웃과 그 뒤의 재시도가 운영 관측(DEV-10)에서 구분되어 보인다.

## 5. 개발자가 각 작업에서 돌려줘야 하는 것

“완료했습니다”만으로 인계가 끝나지 않는다. 작업 카드마다 아래를 반환한다.

1. **변경 요약:** 사용자에게 무엇이 달라졌는지 3줄 이내.
2. **계약:** API 요청·응답·오류 코드, DB 변경, 환경변수. 비밀값은 쓰지 않는다.
3. **마이그레이션:** 적용 순서, 기존 데이터 처리, 되돌리기 또는 되돌릴 수 없는 이유.
4. **검증 증거:** 자동 테스트 결과와 상태별 화면/응답. “직접 눌러 봄”만 적지 않는다.
5. **운영:** 대시보드·알림·배치 일정·담당자·재시도 방법.
6. **배포/롤백:** 기능 플래그, 배포 순서, 롤백 시 데이터 호환성.
7. **남은 위험:** 임시 처리, 알려진 제한, 다음 작업. 없으면 “없음”이라고 쓴다.
8. **문서 갱신:** 이 문서의 카드 상태와 관련 정본 문서. 과거 기록을 새 사실처럼 덮어쓰지 않는다.

## 6. 전체 출시 완료의 정의

- QR 신규 사용자가 로그인 벽이 아니라 홈에서 무료 학습을 시작한다.
- 가입·기록 이전·비밀번호 재설정이 실제 서버와 메일로 끝까지 동작한다.
- 잠금, 결제, 웹훅, 권한 복원, 만료·환불이 서버 상태 하나로 수렴한다.
- 합의한 보호 수준에서 잠긴 콘텐츠가 주소 직접 입력으로 열리지 않는다.
- 표현클립 신고가 저장되고 한 사람의 신고로 전역 삭제되지 않는다.
- 콘텐츠 공개 상태와 음성 보관기간이 빌드·배치에서 자동 강제된다.
- 약관·개인정보 문서가 실제 운영값과 맞고 동의 증거가 남는다.
- 외부 AI가 늦거나 끊겨도 학생이 정해진 시간 안에 다시 시도할 수 있는 화면에 도달한다.
- 미션 대화가 검수된 원장 내용으로 돌고, 브리핑과 완료 판정이 같은 라벨을 본다.
- 계정 데이터 열람·내보내기 요청과 가입 연령 정책이 정해진 방법으로 처리된다.
- CI·오류 수집·핵심 운영 알림·롤백 절차가 있으며 출시 후보 세로 흐름을 통과한다.

이 조건 중 정책 결정이 비어 있으면 개발 완료로 표시하지 않고 해당 PD 번호로 **BLOCKED** 처리한다.
