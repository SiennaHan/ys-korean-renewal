## 0. 역할 경계

| 담당 | 정하는 것 | 하지 않는 것 |
|---|---|---|
| 기획·제품 책임자 | 가격·환불·보관기간·노출 게이트·정확도 기준·최종 법률 문구, 화면 승인 | DB 구조·웹훅 검증·재시도 정책을 감으로 지정하지 않는다 |
| 개발자 | DB 마이그레이션·API·권한·보안·외부 연동·관측·테스트·배포·롤백 | 미정인 가격·보관기간·정답률을 대신 결정하지 않는다 |
| 디자인 | 시각 정본·상태별 문구·다섯 언어 레이아웃 승인 | 결제 성공·권한 부여를 클라이언트 상태만으로 확정하지 않는다 |

앱 코드를 고쳐야 하는 작업도 있다. 다만 개발자가 앱에서 맡는 범위는 **API 배선·오류 상태·접근성·분석 이벤트**다.
승인된 컴포넌트의 색·간격·문구를 바꾸는 것은 별도 디자인 승인을 받는다.

### DEV-01 · QR을 홈으로 보내기 — **완료**(2026-09-01) · P0

**목적:** 책의 QR은 권한 키가 아니라 유입 경로다. 로그인 여부와 무관하게 게스트 세션을
보장한 뒤 홈(`/main`)으로 보낸다.

**했다 (`1253b71`).** `externalRedirectUrl()` 이 운영자가 진짜 외부 URL
(`PUBLIC_QR_WEB_REDIRECT_URL`)을 명시적으로 준 경우가 아니면 `null` 을 낸다 —
전에는 빈 값이면 `/` 로 떨어져 `IntroSection` 의 2초 지연 재확인 경쟁에 걸릴 수 있었다.
추적(`createQrScan`/`reportQrRedirect`) 은 try/catch 로 감싸 절대 이동을 막지 않는다.
게스트 세션은 `useAuth()` 로 `isSignedIn` 을 본 뒤 `if (!isSignedIn)` 일 때만 만들어
이미 로그인한 방문자의 세션을 덮지 않는다. `navigate({to:"/main", replace:true})`
(SPA) 로 이동한다 — 외부 URL 이 설정된 경우만 예외.

**눌러 본 것** — 로컬스토리지를 비운 새 브라우저로 `/qr` 접속 → `/main` 에 곧장 도착,
`/qr/scan` · `/user/sign/guest` · `/qr/scan/…/redirect` 각각 정확히 1회. 이미
로그인한 방문자는 토큰 그대로 유지된 채 `/main` 도착.

**남은 것** — 완료 판정의 "언어 설정 이동 전후 동일" 은 별도로 다시 확인 안 함(코드
경로상 언어는 이 라우트가 건드리지 않아 위험이 낮다고 판단했다).

### DEV-02 · 표현클립 신고를 안전하게 저장하기 — **완료**(2026-09-01) · P0

**목적:** 신고가 실제로 저장되고, 신고 한 건이 영상을 전 사용자에게서 즉시 숨기지 않게 한다.

**한 것 — 순서 그대로**

1. **제외 → 하위 정렬.** `content4.tsx` 의 정렬에 신고 여부를 우선순위보다 앞선 축으로
   넣었다(`compareResults`) — 신고된 구간은 목록에서 안 빠지고 같은 우선순위 안에서
   뒤로 간다. **재생 불가(100·101·150)만** `UNPLAYABLE_CODES` 로 따로 걸러 검색
   결과에서 뺀다.
2. **DB 마이그레이션** (`migration_error_report_segment.sql`, 1번 뒤에 돈다고 파일
   머리에 못박았다) — `target_id` varchar(10)→32. 로컬에서 실제로 신고를 넣어 보다가
   `error_code` 도 varchar(10) 이라 `"audio_quality"`(13자)가 같은 1406 으로 죽는 것을
   찾아 20자로 같이 늘렸다 — 명세에는 없던, 실측으로 찾은 것이다.
3. **구간 단위 저장** — `segment_start`(구간 시작 초)·`matched_line`(걸린 대본 줄) 컬럼을
   새로 두고, 그동안 한 번도 안 쓰인 `content` 칸을 검색어 용도로 재사용했다(rename 안 함).
4. **인증** — `POST /report`·`GET /report/list/{category}` 둘 다
   `dependencies=[Depends(auth.JWTBearer())]`. `user_id` 는 더 이상 요청 바디를 안 믿고
   토큰에서만 뽑는다(`ReportItem.user_id` 필드는 옛 클라이언트 호환용으로 남기되 무시).
5. **슬랙** — `xternal/slack.py` 에 `notifyClipReport` 신설(`notifyInquiry` 자매 함수,
   문의하기와 같은 채널). `&t={start}s` 링크·검색어·걸린 대본 줄·신고자·누적 신고 수를
   담는다. **DB 저장 뒤에** 부르고 실패해도 예외를 안 던진다 — `business/report.py`.
6. **저장 실패 UI** — `ReportBottomSheet` 에 `pending`(연타 방지)·`failed`(빨간 문구 +
   같은 버튼을 다시 누르면 재시도) 상태 추가. 5개 언어 `clip.reportFailed`.

**눌러 본 것** — 로컬 DB 에 마이그레이션을 실제로 돌리고(`DESCRIBE` 로 스키마 확인),
API 서버로 게스트 토큰 발급 → `POST /report`(audio_quality·inappropriate 둘 다) →
`GET /report/list/video` 왕복을 curl 로 확인. 브라우저로는 표현클립 화면에서 실제
검색 → 신고 → **정렬이 그 자리에서 바로 바뀌는 것**(재검색 없이, 17건 중 신고한
구간이 즉시 맨 아래로)을 확인. 서버를 잠깐 내려 저장 실패 화면(빨간 문구)을 띄운
뒤 같은 버튼을 다시 눌러 재시도가 성공하는 것도 확인. 토큰 없는 호출은 401 확인.

**남은 것** — 중복 전송 방지는 **클라이언트의 `pending` 잠금뿐**이다(연타는 막지만
새로고침 뒤 같은 사람이 같은 구간을 또 신고하면 행이 또 쌓이고 `inappropriate` 면
슬랙도 또 온다). DB 유니크 제약은 안 걸었다 — `report_count` 가 부풀 뿐 정렬(존재
여부만 봄)에는 영향이 없어 지금 범위에서는 낮은 위험으로 봤다. 필요해지면
`(category, target_id, segment_start, error_code, user_id)` 유니크가 자리다.

상세 근거는 `BLOCKERS.md` §6-e와 `clip_spec_v1.html` §05~§06이다.

### DEV-12 · 외부 AI 호출의 타임아웃과 실패 화면 — **부분완료**(openai.py 2026-09-01) · P0

**목적:** 외부 응답이 늦으면 학생이 몇 분을 빈 화면에서 기다리는 지금 상태를 없앤다.

**한 것**

1. **`openai.py` 의 모든 호출에 타임아웃을 준다.** 클라이언트 생성 시점에 한 번

   `max_retries=2` 도 같이 명시했다(SDK 기본값을 그대로 적어 둔 것 — §3 참고).
2. **`quest_stream`(미션 대화 스트리밍)이 동기 클라이언트로 서버 전체를 막고

   자리에서 멈췄다 — 대화가 길수록, 동시 사용자가 많을수록 심해지는 문제다.
   `AsyncOpenAI` 를 별도로 두고 `async for` 로 바꿨다. **다만 이 경로는 지금
   앱이 안 쓴다** — `postChat`(`/chat/json`, 비스트리밍)만 부른다(실측:
   `grep -rn quest_stream` → `business/chat.py` 한 곳, 그 라우트
   `/chat/stream/json` 을 부르는 화면이 없다). 그래도 라우트는 살아 있고
   막고 있던 문제가 실재해서 고쳤다.
3. **타임아웃이 있어도 이벤트 루프를 막으면 소용이 적다.** `check_mission`·
   `quest`·`transcribe`·`tts` 넷은 이미 `asyncio.to_thread` 로 감싸 있었는데
   `create_report`·`evaluate_speech`·`translate`·`generate_roleplay_line`·
   `generate_scenario`·`evaluate_speech_flexible` 여섯은 아니었다 — 동기
   호출을 `async def` 안에서 그냥 불러 그 요청이 도는 동안 서버 전체가
   멈췄다. 여섯 다 같은 패턴으로 감쌌다.
4. **`gcloud.py` 는 실은 어디서도 안 부른다.** `business/`·`accepter/` 전체를
   grep 해도 `generateAudio` 를 부르는 곳이 `__main__` 블록뿐이다 — 실제 TTS 는

   것이 STT·TTS 전부" 라고 적어 둔 것이 이 부분만 틀렸다.** 그래도 타임아웃은
   넣었다(`timeout=60.0`) — 되살아나면 그 순간부터 무제한 대기가 시작되고,
   지금 안 넣으면 다음 사람이 또 재발견한다.
5. **앱 쪽 — `postChat` 이 실패(타임아웃 포함)하면 무한 스피너였다.**

   실패하면 `resMsg` 가 영영 안 잡히고 `BotMsgProgress` 가 계속 돌았다 — 사용자는

**현재 — 대부분 이미 돈다.** 이 카드가 늦게 생긴 이유가 그것이다.

- **턴별 판정이 이미 있다.** `POST /chat/check/mission` → `api/business/chat.py:193` →
  `openai.check_mission`(system = `missionPrompt()`, `api/xternal/openai.py:158`).
  발화 1건당 LLM 1회. 네 불리언 + `status` + `feedback` + `recommend_example` 을 낸다.
- **종료 리포트도 있다.** `GET /dialog/{id}/report` → `openai.create_report` → `ko_chat.report`.
- **「나의 문장 피드백」 탭도 구현돼 있다**(`report-screen.tsx:232-250`).
- **★ `recommend_example`(교정 문장)을 서버가 만드는데 앱이 한 번도 그리지 않는다** —
  앱 전체에서 타입 선언(`apiType.ts:74`)과 파싱 기본값(`mission-report.tsx:92`) 둘뿐이다.
  **기획자가 요구한 「고친 문장」이 이미 생성되고 버려진다.**
- **발음 축이 맞음을 안 잰다.** `missionPrompt` 가 `is_pronunciation_correct` 를
  「오타·철자·용언 활용」으로 정의한다 — 텍스트 기반이라 그렇게 만든 것이다.
- **발음 평가 API 는 서버에 이미 있다** — `POST /tutorus/pronunciation`
  (`api/accepter/tutorus_accepter.py:31`), `api/.env` 에 `TUTORUS_*` 6줄.
  **없는 것은 앱 배선뿐이다.**

**구현 범위**

1. `recommend_example` 을 말풍선(`chat-text.tsx:141` `FeedbackBox`)과 리포트 카드에 잇는다.
   새 컴포넌트를 만들지 않는다 — 이유가 이미 그 자리에 있다.
2. 발음 축을 `tutorus_pron` 실측으로 바꾼다. `missionPrompt` 의 그 항목은 **지우지 않고**
   이름표만 「표기(맞춤법)」로 옮긴다(키를 지우면 이미 쌓인 행의 계산이 0% 로 무너진다).
3. 판정과 발음을 `asyncio.gather` 로 **병렬**로 돌린다. **발음 실패·비활성은 전부
   「측정 안 됨」**이고 판정을 지연·실패시키지 않는다.
4. 딸린 결함 — 재접속 시 발화가 사라지는 짝짓기(`mission-dialog.tsx:336-358`,
   `else` 가 없다) · **실패와 오답이 같은 모양**(DEV-12 가 남겨 둔 자리) ·
   총평 캐시 무효화(`dialog.py:38-40`) · 유령 프롬프트 삭제(`openai.py:245-321`).
5. `PROMPT_VERSION` 을 판정 결과에 스탬프한다 — `mission_chat_spec_v1.md` §6 이 요구한다.
6. **원장의 `target_grammar` 를 판정까지 잇는다** — 아래.

**★ 원장에 있는데 판정이 못 보던 값 하나 (2026-09-04 에 이었다)**

`ko_mission_chat.target_grammar`(그 과에서 써야 할 문법)가 **원장에 있고 DB 컬럼도
있는데 판정에 닿지 않았다** — `repo_chat._Dialog` 가 다섯 칸만 노출했다.

처음에는 `_Dialog` 에 칸만 더하고 **프롬프트로는 안 넘겼다.** 그때 커밋 메시지가
「판정에 닿는다」로 읽히게 쓰였는데 사실이 아니었다 — 기획자가 「미션 상태의 주인
문제가 뭐냐」고 물어 다시 보다 찾았다.

지금은 `missionPrompt` 에 `Target Grammar` 슬롯이 있고 「**이것은 완료 조건이
아닙니다**」를 같이 못 박았으며, 출력 스키마에 `target_grammar_used` ·
`target_grammar_evidence` 두 칸을 더했다(`_normalizeCheckMission` 이 빠진 키를 메운다).
원장 값이 판정까지 닿는 것을 대역으로 확인했다 —
`판정이 받은 target_grammar = '이에요/예요 은/는'`.

**남은 것은 그 값을 리포트에서 쓰는 것**이다. 「대화는 잘했는데 목표 문법은 안
썼다」가 그 자체로 학습 데이터라는 게 `mission_chat_spec_v1.md` §3 의 주장이다.

**발음 축이 실제로 재진다 — 2026-09-03 에 확인했다**

기획자가 벤더 테스트 클라이언트(`test_client_korpron`)를 줬다. 그 설정으로 **저장소
코드 경로를 그대로 태워** 실제 응답을 받았다 — 인증 → ffmpeg 16k 리샘플 → korpron →
`summarize` 까지 끊긴 데가 없다.

    KO_HOLISTIC(overall) 90 · segment 90 · speed 88 · prosody 94 · acoustic 60
    wordLevel 13개 (지하철 51 · 시간이어서 70 · 시계를 75 …)

**`api/.env` 에는 키 이름 다섯이 있는데 값이 전부 빈 칸이다** — 그래서 서버가
`PRONUNCIATION_ENABLED=false` 로 떨어져 503 을 낸다. 값은 기획자가 넣는다
(살아 있는 공용 비밀값이라 개발자가 파일에 쓸 일이 아니다).

**남는 것은 운영 승격이다** — 엔드포인트가 `dev.tutorusresearch.com` 이고 계정이
`freewheelin` 공용이며, 배포 서버에 **ffmpeg 가 필요하다**(§3-b). 운영 URL·전용 계정
전에는 「돈다」와 「운영에서 돈다」가 다르다.

**어디까지 확인했나 (2026-09-04)**

`api/.env` 에 Tutorus 값 다섯을 채우고(git 이 `.env*` 로 막는다) **서버 없이
`post_check_mission` 을 직접 태워** 배선을 확인했다. DB 는 진짜다.

| 본 것 | 결과 |
|---|---|
| 발음 실측 | `measured=true score=90` · 취약 낱말 「서둘러 40 · 급하게 48 · 지하철 51」 |
| 실패 경로 | `no_audio` · `no_reference` · `tutorus_400` 전부 「측정 안 됨」. **예외가 위로 안 올라간다** |

**시험 행은 지웠다** — `ko_chat` 1 + `ko_chat_feedback` 3, 남은 행 0.

**★ 못 한 것 — 판정 AI 를 실제로 부르지 못했다.** 이 기계의 `api/.env` 는 **DB 값만
실제고 외부 API 키가 전부 빈 칸이다**(`OPENAI_API_KEY`·`GEMINI_API_KEY`·`RTZR_*`·
`S3_BUCKET` 다). 그래서 판정 응답을 대역으로 두고 **그 뒤 경로만** 태웠다.
판정 품질(프롬프트가 네 축을 옳게 매기나)은 **아직 아무도 안 봤다** —
`DEV-13` 이 「끝까지 대화해서 리포트의 「N개 중 M개」를 본 적이 없다」고 적은 그것이
여전히 남아 있다. **키가 있는 환경에서 마이크로 한 번 돌려야 한다.**

**완료 판정**

- 오답 발화에 **고친 문장과 이유가 둘 다** 뜨고, `perfect` 에는 안 뜬다.
- 리포트 발음 축이 음향 점수 평균이고, **키보드로만 한 대화는 「측정 안 됨」**으로 뜬다.
- 요청이 실패하면 **빨간 오답이 아니라 다시 보내기**로 뜬다.
- 재접속해도 발화가 사라지지 않는다(같은 문장을 두 번 말한 대화로도 확인).

  적어 둔 그것이다. 마이크와 실제 AI 호출이 필요하다.

**남은 큰 것은 이 카드가 아니다** — `mission_chat_spec_v1.md` §3(대화 AI 와 판정 AI 가
서로의 미션 상태를 모른다 → 「AI가 이미 끝난 미션을 다시 묻는다」)이 가장 크고,
프롬프트 두 개의 계약을 다시 짜는 일이라 별건이다. §2 힌트/완료 분리 · §4 STT
`confidence` · §6 나머지 관측 필드도 같은 계열이다. **§5 실패 모드와 §7 발화 길이는
기획자만 정할 수 있다.**

## 3-b. 인계 첫날 체크리스트 — **받아야 하는 것과 건드리면 안 되는 것**

전에는 이것들이 **카드마다 흩어져 있었다.** 「이거 누가 갖고 있어요?」가 카드별로
반복되니 한 곳에 모은다(2026-09-03).

### 받아야 하는 것 — 없으면 그 카드는 시작조차 안 된다

| 무엇 | 어느 카드 | 지금 상태 |
|---|---|---|
| **AWS 자격증명**(S3) + **운영 `S3_BUCKET` 이름** | DEV-06 | **이 저장소를 만든 기계에 없다.** `NoCredentialsError` 로 확인했다(2026-09-03). 버킷 이름을 같이 받아야 한다 — 안 주면 도구가 기본값 `pulley-mock` 을 보고 「공개였던 것 0」을 낸다 |
| **PG 상점 계정 · 테스트/운영 키 · 웹훅 주소** | DEV-04 | `PD-02` 가 아직 안 정해졌다. 사업자 선정이 먼저다 |

`README.md` 의 「돌리려면 받아야 하는 것」은 **로컬 개발환경용**(`app/.env`·`api/.env`)이다.
위 표는 **운영 인계용**이라 겹치지 않는다.

### 건드리면 안 되는 것 — 이 저장소는 여러 세션이 동시에 만진다

**이 문서를 진입점으로 삼으면 `CLAUDE.md` 를 안 거치게 된다.** 그래서 거기 있는
규칙 중 **공유 자원에 걸리는 것만** 옮겨 적는다. 나머지는 `CLAUDE.md` 를 봐라.

- **`app/.env` 를 함부로 고치지 마라.** 다른 세션이 띄운 앱까지 같이 죽는다.
- **`git add -A` 금지.** `git commit --only -- <내가 건드린 경로>` 로 커밋한다.
  남의 작업 중인 변경이 딸려 들어간다 — 실제로 겪었다.
- **커밋 전에 `git status` 를 본다.** `git stash` 는 특히 위험하다 — 동시 작업 중인
  다른 세션의 변경까지 되돌린다.
- **`npm install` 을 하지 마라.** pnpm 전용이고 `package-lock.json` 이 생기면
  프로덕션 빌드가 깨진다.
- **`app/src/shared/data/n*.json` 은 산출물이다.** 손으로 고치지 말고 원장을 고친 뒤
  `build-content.py` 를 돌린다.
- **이 저장소를 공개로 돌리지 마라.** 교재에서 뽑은 문장·어휘·듣기 지문이 추적된 채로 있다.

## 5. 개발자가 각 작업에서 돌려줘야 하는 것

“완료했습니다”만으로 인계가 끝나지 않는다. 작업 카드마다 아래를 반환한다.

1. **변경 요약:** 사용자에게 무엇이 달라졌는지 3줄 이내.
2. **계약:** API 요청·응답·오류 코드, DB 변경, 환경변수. 비밀값은 쓰지 않는다.
3. **마이그레이션:** 적용 순서, 기존 데이터 처리, 되돌리기 또는 되돌릴 수 없는 이유.
4. **검증 증거:** 자동 테스트 결과와 상태별 화면/응답. “직접 눌러 봄”만 적지 않는다.
5. **운영:** 대시보드·알림·배치 일정·담당자·재시도 방법.
6. **배포/롤백:** 기능 플래그, 배포 순서, 롤백 시 데이터 호환성.
7. **남은 위험:** 임시 처리, 알려진 제한, 다음 작업. 없으면 “없음”이라고 쓴다.
8. **문서 갱신:** 이 문서의 카드 상태와 관련 정본 문서. 과거 기록을 새 사실처럼 덮어쓰지 않는다.

**누가 이 보고를 다시 확인하나 — 자기 보고로 끝내지 않는다.** 이 저장소는 `CLAUDE.md` 에서 「내 검사기가 통과했다는 건 그 축에서만 맞다는 뜻」이라고 여러 번 못을 박았는데, 위 여덟 항목은 전부 **개발자 자신의 보고**다. 그래서 병합 전에 이 둘을 남긴다.

- **게이트는 사람 말이 아니라 기계로 확인한다** — 병합하는 쪽이 `pnpm typecheck` · `pnpm parity:activity` · `pnpm build` · `pnpm check:css` · `python3 docs/check_docs.py` 를 **직접 돌린 출력**을 본다. 「통과했습니다」는 증거가 아니다.
- **4번 「검증 증거」는 기획자가 화면으로 본다** — 상태별 화면이 목업 정본과 같은지는 `screen_promotions.md` 의 판정 기준으로 본다. 값이 같은지가 아니라 **조작이 늘거나 줄었는지**를 본다(2026-09-03 에 그 축을 세 번 갈아서 배운 것이다).

## 6. 전체 출시 완료의 정의

- QR 신규 사용자가 로그인 벽이 아니라 홈에서 무료 학습을 시작한다.
- 가입·기록 이전·비밀번호 재설정이 실제 서버와 메일로 끝까지 동작한다.
- 잠금, 결제, 웹훅, 권한 복원, 만료·환불이 서버 상태 하나로 수렴한다.
- 합의한 보호 수준에서 잠긴 콘텐츠가 주소 직접 입력으로 열리지 않는다.
- 표현클립 신고가 저장되고 한 사람의 신고로 전역 삭제되지 않는다.
- 콘텐츠 공개 상태와 음성 보관기간이 빌드·배치에서 자동 강제된다.
- 약관·개인정보 문서가 실제 운영값과 맞고 동의 증거가 남는다.
- 외부 AI가 늦거나 끊겨도 학생이 정해진 시간 안에 다시 시도할 수 있는 화면에 도달한다.
- 미션 대화가 검수된 원장 내용으로 돌고, 브리핑과 완료 판정이 같은 라벨을 본다.
- 계정 데이터 열람·내보내기 요청과 가입 연령 정책이 정해진 방법으로 처리된다.
- CI·오류 수집·핵심 운영 알림·롤백 절차가 있으며 출시 후보 세로 흐름을 통과한다.

이 조건 중 정책 결정이 비어 있으면 개발 완료로 표시하지 않고 **미구현(PD-NN 대기)** 로 적는다.
